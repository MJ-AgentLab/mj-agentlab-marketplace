# 指南框架

本参考用于选择理解目标、编排内容和核对文本交付。结构随材料调整；下面是设计判断维度，不是固定章节模板。

## 材料与证据边界

在选择目标前建立够用的材料清单：材料名称、可定位位置、版本或明确快照、实际读取范围、可支持的主张及未覆盖部分。文件来源可以用相对来源身份和章节或行号，网页用可访问的页面与章节，粘贴内容用本次快照说明；不能编造行号、链接、版本或阅读范围。

区分四类内容：

| 类别 | 如何使用 | 必须保留的边界 |
| --- | --- | --- |
| 原材料 | 指南讲解的对象；关键措辞、规则和关系回到原文 | 用户陈述或提案并不自动成为已经实现或验证的事实 |
| 已核验背景 | 补足必要定义、背景或条件，标出独立来源及核验范围 | 只对实际核验的命题负责；外部新事实不靠模型记忆冒充核验 |
| 教学构造 | 帮助说明规则或误区的虚构情境、数值或角色 | 清楚标“教学构造”，不充当真实记录、原文规定或领域证据 |
| 设计判断 | 说明为什么某种组织或交互适合本次任务 | 设计理由不等于已测量的理解效果 |

材料含有来源冲突时并列保留主张、来源和适用条件；不能为了给出整齐指南自行选边。只有已取得、适用的明确优先规则才能解释如何使用，并保留原冲突。缺少定义、关系、规则或版本时写出缺口及其影响，不用熟悉术语或版式补完。

必要背景有时效性或实质影响答案时，读取可访问的第一手来源再采用。只核验当前问题所需部分。未能核验时标明“未核验”，可收窄指南到已读材料；若缺口阻断关键判断，保留该部分待补，不把同一缺口泛化为全部内容无法推进。

关键原文可按需要短引或忠实转述，紧邻来源定位、条件和限制。摘要、案例或索引不能继承其指向原文的全部权威。教学整理不能改写原材料事实。

来源明确列出的缺口与为本任务新增的检查轴分别标注。新增读者、任务、比较维度或核验建议属于设计判断或有边界的推论；即使合理，也不能统括为“材料明确指出”。引用与归因逐项对应，不让正确的原文条目替同段新增内容提供来源背书。

## 目标选项

每套选项必须同时说清：

- **读者 Audience**：与材料相关的阅读情境、责任和已明确的前置知识，不推断人格、智力或能力等级。
- **使用任务 Task**：阅读后要做的具体判断或说明，如决定何时适用、追踪依据、解释一个分支；不要只写“了解概念”。
- **理解问题 Understanding Questions**：读者要能回答的可观察问题，指出材料能支持的答案或当前缺口。

2–3 套方案应在关注的信息、判断任务或所需深度上有实际差异。只把同一目标换成“初学者／管理者／专家”三个名字不算差异。可按材料选择“建立概念边界”“判断规则适用条件”“追溯依据与限制”等不同重点，不能机械复用这三个标签。

推荐依据是材料完整度、当前任务及读者需求；说明为什么适合、代价是什么。推荐目标不是推荐知识题答案。所有选项保持可修改，用户选定或修改确认前停留在目标选择阶段。

## 从问题到内容

确认后，给每个核心理解问题找到必要原文、关系、条件、例外及来源。先确定要保留的意思，再决定标题、分组、阅读顺序和呈现形式。

| 设计判断 | 应明确什么 |
| --- | --- |
| 内容取舍 | 哪些内容是回答问题必需的；哪些只是背景或补充；删除后是否改变结论 |
| 层级与分组 | 标题和组名的依据；内容从属是否与领域中的包含关系区分 |
| 阅读顺序 | 哪些前提先读；读者需要先得到什么结论；顺序是阅读建议还是原材料规则 |
| 同时比较 | 比较维度是否一致；应放在同一状态中查看的内容与限制 |
| 表达形式 | 精确条件适合文字，沿维度比较适合表格，有依据的连接或分支可用图示描述 |
| 交互 | 操作后增加哪种理解、付出什么代价；静态呈现是否已经足够 |

“概览 Overview → 细节 Detail”可以是常显结论加补充说明，不要求加入展开控件。重要条件、例外、来源状态和需要比较的信息不能靠读者主动发现才出现。

复杂度以材料本身判断：关系种类、分支数量、相互依赖、冲突、例外和目标数量。一个清楚的局部规则通常不需要长课程；多来源或多分支材料应展开必要核对。用户要求短版时优先删去冗余和装饰，保留关键边界，不以篇幅为由隐藏条件。

## 关系与语义忠实 Semantic Fidelity

先确定原文声明了什么，再描述如何表达：

原文术语、中文对照与值类型在所有标签、正文、表格和自检中保持一致。数值、状态等原始变量与由其推导的真假条件分开命名，说明推导依据；不把派生条件当成原术语的新定义。文字压缩、表头或标题不能新增“仅／必须／其他不可”等来源没有的排他量词；原文只描述某情形下的结果时，不扩写为操作仅在该情形可用。

| 关系 | 可考虑的表达 | 常见误读 |
| --- | --- | --- |
| 分类／归组 | 有组名的清单或分类表 | 并列项被当成必经步骤、互斥或穷尽分类 |
| 层级／包含 | 标明关系的树或嵌套描述；多重归属可用表 | 页面层级被当成组件包含，未知归属被强塞进树 |
| 时间／过程 | 时间线、步骤或条件分支描述 | 时间先后被当成因果；分支、循环或可跳过条件被删去 |
| 状态／转移 | 状态表或标明触发条件的转换描述 | 条件满足被当成实际动作已发生；状态与一次动作混用 |
| 依赖 | “谁需要什么”的关系表、矩阵或连接描述 | 依赖被当成运行顺序，多对多被压成单向流程 |
| 因果 | 有依据、条件和范围的因果说明 | 相邻、相关、参数变化或演示被当成真实因果证据 |
| 数值 | 有单位、尺度和来源的表格或数据图描述 | 视觉面积或长度暗示未提供的数量或夸大差异 |

图示描述中每条连接都应有起点、终点、含义、方向、依据和适用条件。标签能澄清主张，不能替主张提供证据。“未说明”不等于“没有”，“可以”不等于“必然”，“本例”不等于“所有情况”；“且／或”“可能／保证”等限定保持原意。

将原材料规则、设计阅读顺序和教学演示顺序分别说明。颜色、空间位置、大小、对齐和图标只辅助已有含义，不能偷偷增加职责数量、等级、顺序或关系。

## 指南交付与核对

按任务选用合适内容：已确认目标和材料范围、内容编排、关键原文及边界、表达关系、必要演示和自检、来源定位、待补项与检查方式。它们可以合并成简洁段落，也可按复杂度分节，没有固定章数或必选控件。

指南要让后续读者知道每个设计服务哪个问题；必要交互使用 [交互设计](interaction-design.md) 中的判准与描述方式。描述教材应呈现什么和如何反馈，保持具体制作工具无关，不写实现代码、配置、命令、文件结构或制作与发布操作。

最终自查覆盖全部核心理解问题：

1. 已确认的读者、任务和问题在指南中一致；没有擅自增加目标。
2. 每个核心结论保留关键原文或忠实转述、来源定位、范围、条件、例外与不保证项。
3. 所有关系及模拟结果有依据；冲突、未知和构造标记保留。
4. 关键内容可见，需要比较的内容可以同时查看。
5. 需要的演示与自检具有操作、变化、结果、反馈和恢复；同一操作的源条件、前置状态及结果在正文、演示、不可用反馈与自检中一致，反例没有误排除允许情形。
6. 深度与篇幅适合材料；交付只含可复制指南文本。

区分拟议检查与已经执行的验证。指南可提出语义、操作及理解任务的检查办法，但当前流程不实际制作或测试教材。设计完整、控件可操作、一次答对或提交完成不证明理解改善、稳定掌握或全面可访问性合规；这些结论需要与对象、任务和范围匹配的额外证据。
