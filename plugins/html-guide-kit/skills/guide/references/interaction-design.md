# 交互设计

本参考用于描述教学交互，不实现或操作教材。只在交互帮助已确认理解问题时采用；静态文字、条件表和并列说明可以成为完整教材内容。

## 每项交互的说明

对需要的交互写清以下内容，可以用短段落或表格，不要求固定格式：

| 内容 | 需要回答的问题 |
| --- | --- |
| 理解用途与依据 | 读者通过操作要核对哪个问题？规则或关系来自哪里？ |
| 起始状态 | 默认看到什么？有哪些已知条件、未知、限制和当前状态？ |
| 操作 | 读者明确选择、调整、前进、回退或提交什么？操作是否必要？ |
| 变化 | 哪部分内容或状态改变？哪些条件、限制或上下文继续可见？ |
| 结果 | 显示了什么？这是模拟结果、参考思路还是有依据的判断？ |
| 反馈 | 为什么发生变化、为何成立或不成立？缺了什么？依据在哪里？ |
| 恢复 | 如何撤销、改选、重试、回退或恢复初始状态？旧反馈何时失效？ |

必要信息不只靠颜色、悬停或动画表达。重要视觉配等价文字说明；操作有清楚名称、状态和文字反馈，考虑键盘、焦点、缩放与窄屏阅读。只描述这些设计要求及待检查范围，不宣称已经完成访问或操作验证。

## 选择模式

- **展开 Disclosure**：用于低频细节或补充理由。入口有意义，展开后保留上下文；需要比较时允许多项同时可见。结论、重要条件及限制常显。
- **切换 View switching**：用于当前无需并列的独立视图。明确当前视图、变化范围和返回方式。并列比较任务优先同时呈现，避免要求记住另一屏。
- **关联高亮 Linked highlighting**：核对原文与表格或图示中已有对应关系。提供文字关系标签、取消选择和非颜色提示，不用高亮制造原材料没有的关联。
- **筛选 Filtering**：在较多条目中寻找相关子集。显示当前条件、结果范围、被隐藏的内容和清除方式；关键例外不被无声过滤。
- **分步 Step-through**：观察有依据的过程、分支或状态变化。保留全局概览、当前位置和触发条件，允许暂停、前进、回退和重置；没有过程依据时不编造步骤。
- **条件模拟 Condition simulation**：让读者探索已给定规则在不同输入下的结果。按下面的完整性门槛确定可判定范围，不把模拟当真实操作或因果验证。
- **教学自检 Learning check**：让读者练习解释规则、关系和边界。按可靠判准门槛区分明确反馈与开放参考，不自动评价能力。

以上是可选模式，不是控件清单或必须覆盖的课时。一个操作说不出具体理解收益，或其成本超过收益时，保留简单静态形式。

## 分步演示

采用同一组明确材料贯穿必要步骤，避免每步更换情境造成理解断裂。每步说明当前事实、操作或触发、改变内容、局部结论及来源；分支、循环、暂停、退出和例外保留，不强行画为单一路线。

演示动作与真实动作分开标明。材料规定需要人为触发时，改变参数或满足条件仅更新“可执行／待触发”等判断，不自动显示动作已经发生或成功。教学中的触发、提交、确认或恢复均标为模拟，不向外部系统执行对应动作。

回退时说明回到哪个状态，是否保留已填写内容；重置时说明清除什么及恢复什么。不能把“恢复初始演示状态”写成真实系统一定可以回到最后成功状态。材料没有保证的行为维持未知。

## 条件模拟：先判断规则是否完整

先读出变量、取值范围、前置条件、分支结果、优先关系、例外及适用范围。只有这些足以覆盖所模拟输入时，才给可判定结果；不得把熟悉的业务惯例补成规则。

| 材料状况 | 指南中的模拟边界 |
| --- | --- |
| 完整规则，所选输入均被覆盖 | 可展开条件组合、边界值和例外；每个结果附理由与依据，仍受材料范围限制 |
| 只规定部分分支 | 仅对已规定分支作判断；其他分支显示“材料未规定，结果待定”及缺少的规则 |
| 缺少阈值、取值范围、触发者或结果 | 明确缺失项，不默认阈值或自动动作；可展示缺口如何阻断判断 |
| 规则互相冲突且无适用的优先规则 | 并列冲突和来源，显示结果不能唯一确定；不选最方便的结果 |
| 为教学另加假设 | 另列“教学构造／假设模型”，清楚说明新增假设及其范围；不得把其输出写成原材料结果 |

规则完整与输入有效分别判断。材料规定了允许值时，越界输入反馈为“超出本模拟规则范围”，不混同某个正常分支。材料没有输入范围时保留未知，不发明范围。

对每个要演示的操作，先从原文核对允许的前置状态、必要条件、触发方式和结果，再判断哪些反例可明确写为不可用。不能把某个操作的前置条件套到另一操作，也不能用名称相近的状态代换。逐步演示、成功与失败反馈、重试及自检中的同一操作应使用同一组源条件；不可用反例不得包含源规则允许的状态。出现内部冲突时回查原文修正，规则不足的分支保持待定，不以“通常如此”补齐。

区分“原文禁止”和“原文未说明”。原文只规定一个状态下的操作结果，不等于其他状态必然不可用，也不保证这些未规定分支的状态或数值保持不变。只有原文明确给出必要条件、排他范围或禁止规则时，才写相应确定的否定反馈；否则该分支标为待补规则，并限定本次演示范围。

固定当前状态和单个操作后再判断。某状态下直接执行一项操作，与先经过其他操作改变状态后再执行，是不同的问题；后者路径缺规则，不撤销前者已由必要条件、排他范围或禁止条款确定的结论。不能用“再次操作甲或操作乙”等一句话，把各自有不同依据的操作统判允许、禁止或未知。拆开操作和路径，分别写已知条件、结果与缺口。

交付前逐处核对正文、模拟表、反馈、边界说明、恢复和自检中的操作断言，重点回查“允许／不可／只能／未规定”。同一当前状态和单个操作的归类应一致；仅路径未规定时把未知限定到该路径，不把源规则明确覆盖的直接操作重新列为未知。

组合条件中的“未知”表示现有信息不足，不自动成为原规则新增的业务取值。先逐项区分已满足、明确不满足和未知，再按原文关系合并：对“且”，任一必要项明确不满足已足以判该组合不满足，其他项未知不能撤销此结论；对“或”，任一备选项明确满足已足以判该组合满足，其他项未知不覆盖此局部结论。其余含未知的组合按缺失信息保留待定，全部已知的组合按原文判断。

上述判断仅针对原文明确给出的条件组合，不代表整个操作可执行、动作已经发生或其他状态、数值可以确定。模拟表和反馈中的分支应互斥，或清楚说明优先顺序；“任一未知”不能同时覆盖已由明确满足或不满足决定的分支。不要为填满表格而把局部可判定结论一概改成未知。

教学构造只用来帮助解释，不能用来填平原材料冲突、消除未知或冒充事实依据。必要构造可简短而明确，仍保持所有源规则限定。原规则缺失但完整教材任务可以继续时，模拟相应部分保持待定，不影响有依据的部分。

指南中的示例输出应包含当前输入、命中的规则或未规定分支、局部结果、限制与恢复方式。“满足前置条件”不能自动变成“验证成功”“动作完成”或“业务通过”。

## 教学自检：先判断判准是否可靠

为每个自检指定要练习的理解问题、材料依据、适用条件与反馈边界。

**有可靠判准时**：答案或判断由明确且适用的材料支持，问题具有可核对的结果；如有多种成立答案，判准应容纳它们，不能为单选形式强造唯一答案。指南说明提交后显示局部判断、理由、常见误区、来源定位和限制，并允许改答、重试或重做。

**没有可靠判准时**：缺少定义或规则、来源冲突、开放设计取舍、答案依赖尚未取得的情境时，采用开放说明与参考思路。参考标明依赖的假设、哪些思路可成立、尚不能判断什么；不伪造标准答案，不自动标正确／错误，不评分。可以让读者说明依据、指出差异并修订，不把未经评阅的自由文本写成已核验。

题目不预选或推荐正确答案，不因沉默、超时或窗口消失推进；目标选择阶段的推荐不能迁移成自检的答案提示。空答或无效答复保持待答，提示需要明确回答，不作为知识错误。

修改答案后，旧判断清除或明确失效；重新提交按当前答案给反馈。重做说明清除哪些选择和反馈，并保留返回材料的方式。允许在看过反馈后再练习，但提示后改答只支持当次反馈后练习事实，不追写为此前已经掌握。

自检设计可以用“已核对”“已提交”等局部状态，不用总分、能力等级或“已掌握”替代观察。一次答对、完成全部操作、表达信心或愿意点击都不能产生长期能力或稳定掌握结论。本技能只描述教材中的自检，不在聊天自动开始测验。

## 交互核对

交付前对指南中实际采用的每项交互检查：用途对应已确认目标；内容和变化有来源；关键条件与限制可见；结果与证据类型一致；完整和缺失规则分开；可靠和不可靠判准分开；反馈解释理由并支持恢复；模拟与真实操作清楚区分。

有需要时在指南中提出后续检查任务：新情境下解释下一步及依据、核对遗漏、定位来源、观察无效操作或往返查找。描述未执行的检查时使用“拟检查”或“需要检查”；不把这份设计、模型演示、局部自检或静态审查写成目标用户理解改善的实证。
