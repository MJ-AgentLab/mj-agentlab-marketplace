# AICS Application

**Lab Proposal / Informative**。本文件为 AICS v0.1 和当前学习解释的原创选编，不是正式标准发布或 Rule adoption。当前学习解释优先解释状态与完成边界；派生速查不冒充原文。来源/范围及实际源字节在 resource-provenance.json。

按完整制作提示词选取的原则核查教材、制作与结果报告：术语一致、表达明确、解释足够、结构表达关系、分层展开、依据与未知明确、执行责任明确。下表是本任务适用视角；未读取完整AICS文本时，不宣称通过全部AICS或AICS-Standard/AICS-Strict检查。中文不机械套用英文词数限制。

| 检查视角 | 本任务的动作 |
|---|---|
| Controlled Language | One Concept, One Term；明确主体、动作与结果；Condition Before Action；保留条件、例外、义务强度、技术标识、数字/单位/日期；Correctness Before Brevity |
| Information Design | 结构表达真实关系；按任务安排结论、必要解释、依据和细节；Explain Enough；重要限制、失败、风险及下一步容易发现。探索练习可以先问问题再展开参考 |
| Epistemic Status | 分开 Confirmed / Inferred / Estimated / Unknown；重要主张有依据，建议说明理由与取舍，假设和未知具体可见 |
| Execution Accountability | 分开 Planned / Attempted / Executed / Verified；报告实际变化、检查对象/方法/结果/未覆盖；按约定目标与必要验收判断完成 |

Evidence 跨上述视角支撑判断，Provenance 保存来源关系。Source-supported 只表示“来源这样说”，核实了来源的表述不等于核实了主张。Confirmed 必须针对具体主张、范围及可检查依据；推断保留前提，估计说明方法，未知说明缺什么及影响。

Verified 只覆盖指定检查；Completed 是 Report Status，需目标、范围、必要执行及验收已达成。必要发布或验证缺失时报告未完成；不能以 Completed with exception 包装核心缺失。少量机器检查或 Agent 合成验收不能证明现实沟通效果或人的理解。

语言分工（英文核心名称/中文解释活动）是本插件约定，用术语一致性原则检查，不声称是 AICS 对所有教材的强制规定。格式与语义分别核验，静态术语检查只能发现已声明映射中的不一致。
