# AICS 精选运行摘要

状态：**Lab Proposal / Informative**。本文件是 communication-kit 对当前学习解释的原创提炼，不是 AICS 正式标准、Rule adoption 记录或现实沟通效果结论。来源与选取映射在 [来源记录](source-provenance.md)，字节身份在 [冻结记录](aics-snapshot.json)。

四类检查是审校视角，按稿件的实际内容应用。读者只需看到成稿和影响采用的关键提示；无需逐项展示标签或把每条消息改成固定报告模板。

| 检查 | 对稿件的检查与修正 |
|---|---|
| Controlled Language | 同一概念保持同一名称；主体、动作和结果明确。把条件与其动作放在一起，保留例外和义务强度。核对引文、技术标识、数字、日期、单位与否定范围。 |
| Information Design | 让读者先找到主要结论、目的或需要决定的事项；依据和细节按需要展开。结构要表达先后、因果、条件或比较关系；把影响判断的限制、失败和风险放在容易看到的位置，明确下一步及其承担者。 |
| Epistemic Status | 对具体 Claim 区分已核实、推断、估计与未知。保留来源归属、假设和核验范围；建议说明理由与主要取舍。语气自信、来源权威或句子更顺畅都不能扩大证据能支持的范围。 |
| Execution Accountability | 对涉及执行的稿件，分开写计划、尝试、实际动作和核验结果。报告检查对象、方法、结果、范围、必要剩余工作与例外，再判断约定目标是否已达成。纯文字表达可不涉及执行检查；涉及执行时该项适用。 |

Evidence 跨项支撑重要判断和执行声明，Provenance 是可追溯的来源关系。四类检查、检查严格度和信息层次分别回答不同问题；不按篇幅判断严格度。

## 来源报告与 Claim 的强度

- **Confirmed**：具体 Claim 在所声明范围内有可检查的核验依据。说明核验对象、结果与限制。
- **Inferred**：从已知材料推导的解释，保留推理所依赖的前提；推导仍可能需要验证。
- **Estimated**：近似或模型判断，按重要性说明方法、假设和范围。
- **Unknown**：证据不足，指出缺口及其对稿件判断的影响。

Source-supported 描述来源关系，不是第五种知识状态。确认“来源这样说”与确认“Claim 本身成立”是不同的核验对象。例如，材料只给出厂商报告时，应写“厂商报告耗时下降 18%”；核对样本与计算后才可报告该样本的均值变化。来源报告和样本变化各自不能单独证明因果或普遍收益。

以上状态用于内部判断，成稿以自然语言保留必要区别；用户未要求时无需逐句加状态标签。

## 核验与完成

Execution State 使用 **Planned → Attempted → Executed → Verified**，每项只覆盖实际动作与取得的依据。Verified 表示明确对象在明确范围内已通过检查。

Completed 是 Report Status。作出完成声明前，核对约定目标、范围、验收条件以及必要执行和核验。配置解析通过只能支持“配置检查通过”；若任务还包含发布而必要发布或验收尚未完成，应报告尚未完成、已达进度和剩余工作。

Completed with exception 仍要求完成门槛已达成，例外仅覆盖已约定的非阻塞事项或范围外限制。必要动作或必要核验缺失时使用未完成状态。Blocked 与 Failed 分别说明阻塞条件或失败点，并保留影响和必要下一步。

模型审校与格式检查可帮助找到遗漏，事实、来源和结果仍要对照可访问的原材料、记录、计算、产物、测试或目标状态。没有对应核验依据时明确实际范围。

## 适用强度与信息层次

所有任务保持事实和含义正确。探索性对话保留假设与未知；常规工作稿补齐重要依据、限制和下一步；高影响决策或执行报告强化关键依据与客观核验。原料不足时先解决关键缺口，不能以正式语气补足证据。

主要答案、支撑依据、展开细节可分层表达；失败、风险、例外若影响采用，应在主要答案附近可见。检查读者能否理解发生了什么、已知与未知、为何重要、下一步是什么；这一读者检查帮助审校，不替代事实核验，也不证明现实效果。
