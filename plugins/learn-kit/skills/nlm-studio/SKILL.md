# nlm-studio · Push a learning topic to NotebookLM as multimedia

## Why this skill exists

`/learn-kit:generate-tier` produces three-tier learning markdown (and
optionally HTML) for a topic — `foundation` for newcomers,
`structural` for those building a mental map, `challenge` for those
moving from comprehension to application. These files are dense and
text-heavy. NotebookLM can transform them into multimedia formats
(podcast-style audio, video, slide decks, mind maps, infographics)
that suit different study contexts (commute, meeting prep, poster
review).

This skill bridges the two: it uploads a topic's full three-tier
corpus to a single NotebookLM notebook, then generates 5 artifact
types × 3 view variants = up to 15 artifacts — each prompted to
*preserve the pedagogical purpose of its source view*. Output is
terminal-only (URLs to view online); nothing is downloaded.

## When to invoke

Invoke whenever the user expresses any intent matching the trigger
phrases in the frontmatter `description`. Do not wait for them to
say "nlm-studio" — the phrase "audio version of `<topic>`" or "上传
到 NotebookLM" should be enough.

The single positional argument is `<topic-slug>` — the folder name
under `learning/`. If the user omits it, scan `learning/*/` and
prompt them to pick one.

## Session sizing recommendation

Step 4 runs up to 15 `studio_create` calls sequentially. ETA is
7–15 minutes depending on artifact size. The skill itself uses
modest context (each poll is a few KB; total ~600 KB across the
batch), but if the user's current session has already consumed
significant context, the trailing minutes of the batch may bump
against the window. **Suggest the user start nlm-studio in a fresh
session if their current session has < 200k tokens remaining.**
This is a soft hint, not a hard gate.

## Step 1 · Pre-flight

1. **Resolve `<topic-slug>`.**
   - If the user passed it as an argument, use it directly.
   - Otherwise, `Glob learning/*/[LEARNING]_*_foundation.md` to
     enumerate available topics, then ask the user via
     AskUserQuestion to pick one.

2. **Check learning files exist.**
   - Three `.md` files are **required**:
     `learning/<topic>/[LEARNING]_<topic>_foundation.md`,
     `learning/<topic>/[LEARNING]_<topic>_structural.md`,
     `learning/<topic>/[LEARNING]_<topic>_challenge.md`.
   - If any `.md` is missing → abort with message:
     "学习文档不完整。请先跑 `/learn-kit:generate-tier <topic>`
     生成三档 markdown 后再调用本 skill。"
   - Three `.html` files are **optional** (foundation/structural/
     challenge `.html`). If all three exist → use 6 sources. If any
     are missing → degrade to 3 `.md`-only sources and warn the
     user: "HTML 渲染未发现 — 仅上传 3 个 .md 作为 source。如想
     用 HTML，请先跑 `/learn-kit:generate-tier <topic>` 的 step 8
     渲染 HTML。"

3. **Auth + service health.**
   - Call `mcp__plugin_learn-kit_notebooklm-mcp__refresh_auth`.
     Failure → abort: "NLM auth refresh failed. Please run
     `! nlm login` in your terminal, then re-invoke this skill."
   - Call `mcp__plugin_learn-kit_notebooklm-mcp__server_info`.
     Failure → abort: "NLM MCP service appears degraded
     (server_info failed). Retry later."

## Step 2 · Re-run guard

Compute the canonical notebook name: `learn-kit:<topic>`.

Call `notebook_list` and search by name. If found, ask the user
via AskUserQuestion which of these to do:

1. **Regenerate artifacts** — reuse the existing notebook and its
   current sources; Step 4 will use `studio_status` to skip
   already-generated `(artifact_type, view)` pairs so you only
   produce what's missing. Good for resuming after CTRL+C.
2. **Replace sources** — `source_delete` the existing 6 (or 3)
   sources, then `source_add` fresh ones. Use when the underlying
   `learning/<topic>/` files have been re-generated and you want
   NLM to re-read them. Existing artifacts are kept (run option 1
   afterward if you want to regenerate them).
3. **Create new notebook** — name will be
   `learn-kit:<topic>-<ISO8601-compact-timestamp>`. The original
   notebook is untouched. Use for A/B comparisons.
4. **Abort** — leave everything as is.

Note: There is intentionally no "append-keep-old sources" option.
NotebookLM does not deduplicate sources by content hash, so an
additive path would silently produce 12 sources of mixed vintages,
confusing both the user (NLM web UI shows 12 source tiles) and the
LLM at generation time. Users wanting truly additive behavior must
add sources via the NLM web UI manually.

## Step 3 · Notebook setup

If the re-run guard chose "create new notebook" or no existing
notebook was found, call `notebook_create(name="learn-kit:<topic>"
[+ optional timestamp suffix])`.

Then upload sources:

- Build the file list (6 files when HTML is present, 3 otherwise),
  ordered: foundation `.md`, foundation `.html`, structural `.md`,
  structural `.html`, challenge `.md`, challenge `.html`.
- For each file, call
  `source_add(notebook_id, source_type="file",
              file_path=<absolute-path>, wait=True)`.
- **L2 fallback for `.html`:** If `source_add` raises a
  format/mime error for an `.html` file, retry with
  `source_type="text"`, passing the file contents read by the
  `Read` tool. Title the source with the basename for clarity.
  The fallback is defensive: NotebookLM's `source_type="file"`
  is well-tested for `.md` / `.pdf` / `.txt`, but `.html`
  ingestion is less commonly used and may be rejected by mime
  detection on some source paths. Falling back to plain text
  ingestion preserves the content; the file's structure (CSS,
  inline scripts, etc.) is irrelevant to NLM's downstream
  artifact generation anyway.
- On any other failure: skip that file, continue, and surface in
  the final recap.

## Step 3.5 · Quota confirm gate (CRITICAL)

Before any `studio_create` is fired, present this confirmation via
AskUserQuestion:

> About to generate up to 15 artifacts on notebook
> `learn-kit:<topic>` — 5 types × 3 views (audio + video +
> slide_deck + mind_map + infographic, each in foundation +
> structural + challenge).
>
> Estimated ETA: 7–15 min. Estimated NLM Studio quota usage: 15
> operations, which is roughly 75% of the empirical ~20/day
> ceiling per account.
>
> ⚠️ This skill cannot detect prior same-day Studio usage on your
> NotebookLM account. If you have already generated other Studio
> artifacts today, the batch will fail mid-way when the daily
> quota runs out. Reduce the subset below accordingly.

Options:
1. **Confirm all 15** — proceed with full batch.
2. **Reduce subset** — open a secondary prompt where the user
   multi-selects which `artifact_type` × `view` cells to keep.
   Persist their selection as the loop's working set.
3. **Abort**.

This gate is mandatory because the quota cost is high and we have
no API visibility into prior usage. Failing mid-batch leaves a
partial notebook that the user must resume — easier to right-size
the request up front.

## Step 4 · Artifact generation

**Pre-loop idempotency lookup.** Call `studio_status(notebook_id)`
to fetch the list of artifacts already present on the notebook.
Build a set of `(artifact_type, view)` pairs already covered.
Skip any pair in this set during the generation loop and record
it as `previously-generated` in the recap. This is what makes a
CTRL+C resume safe — no local progress file is needed.

**Loop.** For each `view` in `[foundation, structural, challenge]`
and each `artifact_type` in `[audio, video, slide_deck, mind_map,
infographic]`, in that order (foundation first because it warms
NLM's context most gently):

1. If `(artifact_type, view)` is already-generated → skip.
2. Build `focus_prompt` via the composition contract in
   §"focus_prompt composition contract" below (read view-prefix
   template + artifact-suffix template + any matching
   interaction-override entry). **Run the §Failsafe semantics
   check on the loaded view-prefix template before composing**
   — this catches mid-session template damage or stubbing that
   would otherwise silently strip the View-Purpose Preservation
   principle.
3. Call `studio_create(notebook_id, artifact_type, focus_prompt,
   view=view, confirm=True)`.
4. Poll `studio_status` every 15 seconds. Cap at 20 polls (5 min)
   per artifact. On `completed` → collect `artifact_id` + URL.
   On timeout → record status `polling-timeout-but-may-complete`
   and move on (the artifact may still complete server-side; the
   user can refresh in NLM web UI).
5. On `studio_create` failure (format error, quota hit, NLM 5xx):
   record `skipped-error` with the error text, continue with the
   next pair. Do not retry — the user re-invokes the skill if they
   want to retry, and Step 4's idempotency lookup will pick up
   only the missing ones.

## Step 5 · Terminal recap

Print a markdown table to the terminal:

```
## NLM Artifacts for `<topic>`

Notebook URL: <notebook_url>

| # | Artifact Type | View | Status | URL |
|---|---------------|------|--------|-----|
| 1 | audio | foundation | newly-generated | <url> |
| 2 | audio | structural | newly-generated | <url> |
| … | … | … | … | … |
```

After the table, add:

> URLs are not persisted to your local repository. If you want a
> permanent record, bookmark the notebook URL in your browser or
> save the table to your own notes.

Possible status values:
- `newly-generated`
- `previously-generated`
- `polling-timeout-but-may-complete`
- `skipped-error: <reason>`
- `skipped-by-subset` (user de-selected this cell in Step 3.5)

## Failure modes summary

| Stage | Failure | Behavior |
|-------|---------|----------|
| 1 | `nlm login` not done / token expired | Abort, instruct user to run `! nlm login`. |
| 1 | `server_info` fails | Abort, "service degraded, retry later". |
| 1 | A required `.md` missing | Abort, instruct user to run `/learn-kit:generate-tier <topic>`. |
| 1 | An `.html` missing | Degrade to 3-source mode, warn, continue. |
| 3 | `source_add` file rejected (mime) | L2 fallback to `source_type="text"`, retry once. |
| 3 | `source_add` fails entirely | Skip that source, continue, surface in recap. |
| 3.5 | User selects "Reduce subset" | Run only the user-selected `(type, view)` cells. |
| 3.5 | User selects "Abort" | Exit cleanly. Notebook + already-added sources remain. |
| 4 | Single `studio_create` errors | Mark `skipped-error`, continue with next cell. |
| 4 | Single artifact polling timeout | Mark `polling-timeout-but-may-complete`, continue. |
| 4 | NLM 5xx during studio_create | Mark `skipped-error`, continue. Repeated 5xx is not auto-retried. |
| 5 | — | Always print recap, even on partial success. Recap surfaces the failure count. |

## focus_prompt composition contract (§4.5 of design plan)

The skill ships three view-prefix templates (one per learning view)
and five artifact-suffix templates (one per artifact_type). Plus a
small interaction-overrides table for the few (view × artifact)
cells where the joint effect needs explicit tuning.

Composition at runtime:

```
focus_prompt = """
===== VIEW PURPOSE =====
{contents of templates/view-{view}.md, ~80 lines}

===== MEDIUM CONSTRAINTS =====
{contents of templates/artifact-{type}.md, ~30 lines}

===== INTERACTION OVERRIDE =====
{the `inject:` value from interaction-overrides.md if a row exists
 for this (view, type) pair; otherwise omit this section entirely}

===== SOURCE TOPIC =====
Topic: {topic}
View: {view}
Source files: {6 (3 md + 3 html) | 3 (md only)}
"""
```

**Why this design over 15 standalone templates:** view and artifact
have largely independent dimensions. The view carries the
pedagogical *purpose* (who's listening, what they must learn) and
the artifact carries the medium *format* (how long, how dense,
what structure). The 15 cells share patterns along both axes;
maintaining them as 8 composable files instead of 15 monoliths is
DRY-er and easier to evolve. The interaction-overrides table
handles the minority of cells where the joint effect surprises.

**Failsafe semantics.** Before composing each artifact's
`focus_prompt`, verify the loaded view-prefix template against
this checklist:

1. All five `## §<N>` headers are present, in order, with the
   exact slugs: §1 Pedagogical purpose / §2 Audience profile /
   §3 Style mandate / §4 Anti-patterns / §5 Success criteria.
2. Each of those five sections has at least one non-blank
   body line (i.e., the heading is followed by substantive
   content, not just whitespace before the next heading).

If either check fails, abort the whole skill — the View-Purpose
Preservation principle (the reason this skill produces
tier-faithful artifacts rather than generic ones) breaks down if
the view-prefix is incomplete or stubbed. Tell the user which
view template is broken, which check failed, and where to fix it
before retrying.

The failsafe runs once per artifact (not just once per session)
because the 15-artifact loop is long-running, and a template
change mid-session (e.g., the user editing a view file in
another window) should be detected, not silently ignored. The
cost is negligible — re-reading a ~80-line template is cheap.
