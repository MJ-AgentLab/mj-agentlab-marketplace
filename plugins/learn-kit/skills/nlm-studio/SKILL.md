# nlm-studio · Push a learning topic to NotebookLM as multimedia

## Why this skill exists

`/learn-kit:generate-tier` produces three-tier learning markdown (and
optionally HTML) for a topic — `foundation` for newcomers,
`structural` for those building a mental map, `challenge` for those
moving from comprehension to application. These files are dense and
text-heavy. NotebookLM can transform them into multimedia formats
(podcast-style audio, video, slide decks, mind maps, infographics)
that suit different study contexts (commute, meeting prep, poster
review).

This skill bridges the two: it uploads a topic's three-tier markdown
corpus to a single NotebookLM notebook, then generates 4 view-cycled
artifact types × 3 view variants + 1 shared mind_map = up to 13
artifacts — each prompted to *preserve the pedagogical purpose of
its source view* (where applicable). Output is terminal-only (URLs
to view online); nothing is downloaded.

## Outputs at a glance

This skill generates up to **13 NotebookLM artifacts per topic**, all
viewed online at `notebooklm.google.com`:

- **12 view-cycled artifacts** — audio + video + slide_deck +
  infographic, each in foundation / structural / challenge view
  variants. Each cell is prompted to preserve the pedagogical purpose
  of its source view (View-Purpose Preservation principle; see
  Dogfood finding #5 below + the `focus_prompt composition contract`
  section near the end of this skill).
- **1 shared mind_map** — view-agnostic per topic (NLM's mind_map
  artifact type produces structural-hierarchy output regardless of
  view-prefix prompting; one mind_map per topic, not three).

Sources per topic are **3 markdown files** (foundation / structural /
challenge tier from `learning/<topic>/`). HTML files from
`/learn-kit:generate-tier` are intentionally NOT uploaded — NLM
rejects non-trivial HTML in both file-mode and text-mode source_add
(Dogfood finding #2); HTML rendering is for human browser viewing
only.

Notebook is named `learn-kit:<topic>`. If it already exists, the
user is asked to regenerate / replace sources / new-timestamped /
abort (see Step 2 · Re-run guard). Append-keep-old is intentionally
not offered.

Output is **terminal-only** — a markdown table of NLM URLs. No local
disk write, no INDEX update, no binary download.

## Dogfood-validated design (v1.0.0)

The 5-step workflow below was validated end-to-end against
an external Claude Code project's `learning/documentation-framework/`
topic. Five findings shaped the final design:

1. NLM's `refresh_auth` + `server_info` are local-only checks — they
   confirm tokens exist on disk and are recent, but say nothing about
   whether Google still accepts them. **Step 1 therefore requires a
   real network ping** (notebook_list) as the actual auth gate.
2. NLM rejects `.html` source uploads in both file-mode and text-mode
   for non-trivial content (even after attempted text-mode fallback).
   **HTML upload has been dropped entirely**; only `.md` files are
   uploaded. The HTML output of `/learn-kit:generate-tier` is for
   human browser viewing, not NLM ingestion.
3. NLM tokens are short-lived (~15-30 min observed). **Each Step
   refreshes auth before its first network call**, and mid-run auth
   failures are retried once before abort.
4. `source_add` error responses are unreliable — the server may
   succeed asynchronously even after the client receives an error.
   **Always verify the actual notebook state via notebook_get** after
   batch uploads; trust the verified list over the source_add
   responses.
5. NLM's `mind_map` artifact type defaults to structural-hierarchy
   output regardless of focus_prompt — view-purpose differentiation
   fails for this medium. **Mind_map is generated once per topic**
   (not per view); the other 4 artifact types remain view-cycled and
   preserve view-purpose strongly.

## When to invoke

Invoke whenever the user expresses any intent matching the trigger
phrases in the frontmatter `description`. Do not wait for them to
say "nlm-studio" — the phrase "audio version of `<topic>`" or "上传
到 NotebookLM" should be enough.

The single positional argument is `<topic-slug>` — the folder name
under `learning/`. If the user omits it, scan `learning/*/` and
prompt them to pick one.

## Auth & prerequisites

- **MCP server**: `notebooklm-mcp` (configured by this plugin's
  `.mcp.json`; auto-loaded on plugin install)
- **One-time terminal command**: user must run `! nlm login` once in
  their terminal to authorize the MCP server against NotebookLM
- **Token lifetime**: NLM tokens are short-lived (~15-30 min); this
  skill refreshes auth before each Step's first network call and
  retries once on mid-run expiry (see Step 1.4 and Step 4 for the
  failure modes covered)

The View-Purpose Preservation quality principle (which makes
foundation/structural/challenge variants of the same artifact type
sound / look meaningfully different) is enforced via composable
view-prefix + artifact-suffix prompt templates. See the
`focus_prompt composition contract` section near the end of this
skill for the full mechanism; failsafe semantics there abort the
whole skill if a view-prefix template is incomplete.

## Session sizing recommendation

Step 4 runs up to 13 `studio_create` calls in 3 parallel batches of
5 + 1 final solo. Wall-clock ETA is 7–15 minutes including NLM-side
artifact generation. The skill itself uses modest context (each
batch is a few KB; total ~600 KB across the full run). If the user's
current session has < 200k tokens remaining, suggest a fresh session
to avoid bumping the context window in the trailing minutes.

## Step 1 · Pre-flight

1. **Resolve `<topic-slug>`.**
   - If the user passed it as an argument, use it directly.
   - Otherwise, `Glob learning/*/[LEARNING]_*_foundation.md` to
     enumerate available topics, then ask the user via
     AskUserQuestion to pick one.

2. **Check the 3 required markdown files exist.**
   - Required:
     `learning/<topic>/[LEARNING]_<topic>_foundation.md`,
     `learning/<topic>/[LEARNING]_<topic>_structural.md`,
     `learning/<topic>/[LEARNING]_<topic>_challenge.md`.
   - If any is missing → abort with message: "学习文档不完整。
     请先跑 `/learn-kit:generate-tier <topic>` 生成三档 markdown
     后再调用本 skill。"
   - HTML files are intentionally not consulted (see dogfood finding
     #2). Their absence is normal and expected.

3. **Auth + service health (local checks).** Call
   `mcp__plugin_learn-kit_notebooklm-mcp__refresh_auth` and
   `mcp__plugin_learn-kit_notebooklm-mcp__server_info`. Both should
   report `success`. Note these are local-only checks (token presence
   on disk + freshness timestamp); they do NOT verify the token is
   still accepted by Google.

4. **Real auth verification (network ping).** Call
   `mcp__plugin_learn-kit_notebooklm-mcp__notebook_list` (no args).
   This is the actual auth gate.
   - On `Authentication expired` error: instruct the user to run
     `! nlm login` in their terminal, then re-invoke the skill.
     Abort cleanly.
   - On other network errors: instruct the user to retry later and
     abort.

## Step 2 · Re-run guard

Refresh auth at start of step:
`mcp__plugin_learn-kit_notebooklm-mcp__refresh_auth`.

Compute the canonical notebook name: `learn-kit:<topic>`. The
notebook_list result from Step 1.4 is still fresh; reuse it.

If found, ask the user via AskUserQuestion which of these to do:

1. **Regenerate artifacts** — reuse the existing notebook and its
   current sources; Step 4 will use `studio_status` to skip
   already-generated `(artifact_type, view)` pairs so you only
   produce what's missing. Good for resuming after a partial run.
2. **Replace sources** — `source_delete` the existing markdown
   sources, then `source_add` fresh ones. Use when the underlying
   `learning/<topic>/*.md` files have been re-generated and you want
   NLM to re-read them. Existing artifacts are kept (run option 1
   afterward if you want to regenerate them).
3. **Create new notebook** — name will be
   `learn-kit:<topic>-<ISO8601-compact-timestamp>`. The original
   notebook is untouched. Use for A/B comparisons.
4. **Abort** — leave everything as is.

Note: There is intentionally no "append-keep-old sources" option.
NotebookLM does not deduplicate sources by content hash, so an
additive path would silently produce duplicate sources of mixed
vintages, confusing both the user and the LLM at generation time.
Users wanting truly additive behavior must add sources via the NLM
web UI manually.

## Step 3 · Notebook setup

Refresh auth at start of step:
`mcp__plugin_learn-kit_notebooklm-mcp__refresh_auth`.

If the re-run guard chose "create new notebook" or no existing
notebook was found, call `notebook_create(title="learn-kit:<topic>"
[+ optional timestamp suffix])`.

Then upload the 3 markdown sources. They can be issued in parallel
(dogfood-validated: 3 parallel file-mode source_adds incurred no
rate limiting). Order them foundation → structural → challenge for
display consistency in the NotebookLM web UI.

For each file:
`source_add(notebook_id, source_type="file",
            file_path=<absolute-path>, wait=True)`.

**Critical post-upload verification (dogfood finding #4):** After
the 3 source_add calls, **always call notebook_get and cross-check
the returned source list**. Some source_add invocations may return
an error response while the server-side ingestion actually
succeeded. The notebook_get response is authoritative — trust it
over the source_add response.

- If notebook_get shows all 3 .md sources present → proceed.
- If a source is genuinely missing (server-side failure, not just an
  unreliable error response) → retry source_add for that specific
  file once. If it still fails, surface the failure in the final
  recap and proceed with the remaining sources (degraded but not
  aborted).

## Step 3.5 · Quota confirm gate (CRITICAL)

Refresh auth at start of step.

Before any `studio_create` is fired, present this confirmation via
AskUserQuestion:

> About to generate up to 13 artifacts on notebook
> `learn-kit:<topic>` — 4 view-cycled types × 3 views (audio +
> video + slide_deck + infographic, each in foundation + structural
> + challenge) + 1 shared mind_map.
>
> Estimated ETA: 7–15 min. Estimated NLM Studio quota usage: 13
> operations, roughly 65% of the empirical ~20/day ceiling per
> account.
>
> ⚠️ This skill cannot detect prior same-day Studio usage on your
> NotebookLM account. If you have already generated other Studio
> artifacts today, the batch will fail mid-way when the daily
> quota runs out. Reduce the subset below accordingly.

Options:
1. **Confirm all 13** — proceed with full batch.
2. **Reduce subset** — open a secondary prompt where the user
   multi-selects which `(artifact_type, view)` cells (plus the
   optional shared mind_map) to keep. Persist their selection as
   the loop's working set.
3. **Abort**.

This gate is mandatory because the quota cost is high and we have
no API visibility into prior usage. Failing mid-batch leaves a
partial notebook that the user must resume — easier to right-size
the request up front.

## Step 4 · Artifact generation

Refresh auth at start of step.

**Pre-loop idempotency lookup.** Call `studio_status(notebook_id)`
to fetch artifacts already present on the notebook. Build a set of
`(artifact_type, view)` pairs already covered (mind_map is keyed by
just `artifact_type` since it's view-agnostic). Skip any pair in
this set during the generation loop and record it as
`previously-generated` in the recap. This is what makes a partial-
run resume safe — no local progress file is needed.

If `studio_status` itself errors (dogfood observed this on empty
notebooks), treat the existing-artifact set as empty and proceed.

**Generation strategy — parallel batches of 5:**

The original sequential design was simplified after dogfood
validated that 5 parallel `studio_create` calls per round incur no
rate limiting. The new flow is:

- **Round 1 (foundation, 5 parallel calls):** audio + video +
  slide_deck + mind_map + infographic, each with view=foundation
  composed focus_prompts. Note: mind_map call in this round uses
  the view-agnostic composition (see §"focus_prompt composition
  contract" below) — there's only ONE mind_map for the whole topic.
  In round 1 we issue the mind_map; rounds 2 and 3 skip mind_map.
- **Round 2 (structural, 4 parallel calls):** audio + video +
  slide_deck + infographic, view=structural. Mind_map skipped (only
  1 per topic).
- **Round 3 (challenge, 4 parallel calls):** audio + video +
  slide_deck + infographic, view=challenge. Mind_map skipped.

Total: 5 + 4 + 4 = 13 artifacts.

For each `studio_create`:

- Build `focus_prompt` via the composition contract below.
- Call `studio_create(notebook_id, artifact_type, focus_prompt,
  confirm=True, ...)`. Note: the API has no `view` parameter — the
  view tier is conveyed entirely through `focus_prompt`. For audio
  use `audio_format="deep_dive"`; for video use `video_format=
  "explainer"`; for slide_deck use `slide_format="detailed_deck"`;
  for infographic use `infographic_style="auto_select"`.
- mind_map is a synchronous API: the response includes the
  generated JSON directly. The other 4 types are async — the
  response contains `artifact_status="in_progress"` and you can
  query progress via `studio_status` if desired (or just direct
  the user to the NotebookLM web UI to watch them complete).

**Between rounds:** refresh_auth. NLM tokens can expire even within
a single Step 4 execution (dogfood finding #3).

**Mid-run auth failure (dogfood finding #3):** If any
studio_create call returns "Authentication expired" mid-round:

1. Refresh_auth.
2. Retry the failed call once.
3. If still failing, abort the loop and produce a recap showing
   which artifacts succeeded so far. Tell the user to run
   `! nlm login` and re-invoke (Step 2 re-run guard will offer
   regenerate to pick up where we stopped).

**Other failure modes** (quota hit, format error, NLM 5xx):
record the failure with status `skipped-error: <reason>` and
continue with the next call. Do not auto-retry these — the user
re-invokes the skill if they want to retry, and Step 4's
idempotency lookup will pick up only the missing artifacts.

| 2 | audio | structural | newly-generated | <url> |

| 5 | video | structural | newly-generated | <url> |
| 6 | video | challenge | newly-generated | <url> |
| 7 | slide_deck | foundation | newly-generated | <url> |
| 8 | slide_deck | structural | newly-generated | <url> |
| 9 | slide_deck | challenge | newly-generated | <url> |
| 10 | infographic | foundation | newly-generated | <url> |
| 11 | infographic | structural | newly-generated | <url> |

After the table, add:

> URLs are not persisted to your local repository. If you want a
> permanent record, bookmark the notebook URL in your browser or
> save the table to your own notes. Most artifacts are async and
> may still be generating in NotebookLM 5–10 minutes after this
> recap; visit the notebook URL to see them complete.

Possible status values:
- `newly-generated`
- `previously-generated` (skipped per idempotency lookup)
- `skipped-by-subset` (user de-selected in Step 3.5)
- `skipped-error: <reason>` (mid-run failure; continued)
- `aborted` (mid-run auth failure that retry couldn't fix)

## Failure modes summary

| Stage | Failure | Behavior |
|-------|---------|----------|
| 1.3 | refresh_auth or server_info fails | Abort: local-only checks should be silent; failure suggests env issue. |
| 1.4 | notebook_list reports auth expired | Abort, instruct user to run `! nlm login`. |
| 1.4 | notebook_list other error | Abort, "service degraded, retry later". |
| 1.2 | A required `.md` missing | Abort, instruct user to run `/learn-kit:generate-tier <topic>`. |
| 3 | source_add returns error (single) | Verify with notebook_get; if source ended up uploaded despite error → continue; if truly missing → retry once. |
| 3.5 | User selects "Reduce subset" | Run only the user-selected cells. |
| 3.5 | User selects "Abort" | Exit cleanly. Notebook + already-added sources remain. |
| 4 | Single `studio_create` errors (non-auth) | Mark `skipped-error`, continue with next cell. |
| 4 | Single artifact polling timeout | Mark `polling-timeout-but-may-complete`, continue. |
| 4 | Auth expired mid-round | refresh_auth + retry once; if still failing, abort with partial recap. |
| 5 | — | Always print recap, even on partial success. Recap surfaces the failure count. |

## focus_prompt composition contract

The skill ships 3 view-prefix templates (one per learning view) and
5 artifact-suffix templates (one per artifact_type). Plus a small
interaction-overrides table for the few (view × artifact) cells
where the joint effect needs explicit tuning.

### Composition for the 4 view-cycled types (audio / video / slide_deck / infographic)

```
focus_prompt = """
===== VIEW PURPOSE =====
{contents of templates/view-{view}.md, ~120 lines}

===== MEDIUM CONSTRAINTS =====
{contents of templates/artifact-{type}.md, ~30 lines}

===== INTERACTION OVERRIDE =====
{the `inject:` value from interaction-overrides.md if a row exists
 for this (view, type) pair; otherwise omit this section entirely}

===== LANGUAGE & TERMINOLOGY =====
{contents of templates/language-directive.md — see §"Language &
 terminology directive" below; appended verbatim to every artifact}

===== SOURCE TOPIC =====
Topic: {topic}
View: {view}
Source files: 3 .md learning documents (foundation/structural/challenge tier)
This is the {view}-tier {type}. It must be distinguishable from the
other view variants of {type} by the View-Purpose criteria above.
"""
```

### Composition for the shared mind_map (view-agnostic)

```
focus_prompt = """
===== MEDIUM CONSTRAINTS =====
{contents of templates/artifact-mind_map.md, ~30 lines}

===== LANGUAGE & TERMINOLOGY =====
{contents of templates/language-directive.md — same single block
 also used by view-cycled composition}

===== SOURCE TOPIC =====
Topic: {topic}
This mind_map is the structural skeleton of the topic across all
three tiers. It is view-agnostic (dogfood finding #5: NLM's
mind_map artifact type produces structural-hierarchy output
regardless of view-prefix prompting; producing 3 view-cycled
variants yields near-duplicate JSONs). One mind_map per topic.
Sources: 3 .md learning documents covering foundation/structural/
challenge tier content.
"""
```

### Language & terminology directive (single shared block)

The directive at `templates/language-directive.md` is loaded
unmodified into every artifact's focus_prompt (both view-cycled
and shared mind_map). It enforces a consistent output-language
policy across all 13 artifacts:

- **Narrative content in 中文 (Simplified Chinese)** — section
  titles, explanations, descriptions, host dialogue (audio),
  on-screen text (video / infographic), slide bodies, mind_map
  node labels.
- **Industry-standard technical terms remain in English** where
  English is the universal convention in the topic's professional
  domain (e.g., `frontmatter`, `schema`, `ADR`, `SKILL.md`, `PR`,
  `track`, `canonical`, `deprecated`, `YAML`, `Markdown`, `MCP
  server`, `loader`, `governance`).
- **Code, file paths, identifiers, command names stay verbatim**
  in their original form (e.g., `mcp__plugin_learn-kit_*`,
  `notebook_id`, `/learn-kit:nlm-studio`).

This single-block approach was chosen over per-template duplication
to (a) guarantee consistency across all 13 cells and (b) make
future policy changes a one-file edit. Edit
`templates/language-directive.md` to adjust the policy globally.

**Dual-lock reinforcement (v2.0.1+)**: dogfood revealed that some
audio / video artifacts still defaulted to all-English output despite
the language directive. To reinforce the constraint, two changes
were applied:

1. `templates/language-directive.md` now opens with a hard mandate
   `**OUTPUT LANGUAGE: 简体中文**` + an explicit failure-mode
   ban ("no full-English narration / dialogue allowed"), positioned
   at the top of the directive block for maximum model attention.
2. `templates/artifact-audio.md` and `templates/artifact-video.md`
   each carry a `## Spoken language` / `## Narration language`
   section inside their `===== MEDIUM CONSTRAINTS =====` segment,
   restating the Chinese-narration rule with medium-specific
   guidance (host dialogue / single narrator / on-screen text).
   These sections defer to LANGUAGE & TERMINOLOGY for the term
   list and mixed-language rules, forming a double lock.

`slide_deck`, `infographic`, and `mind_map` rely only on the single
LANGUAGE & TERMINOLOGY lock — dogfood did not observe English-
defaulting failures in these media. Add a medium-specific
reinforcement section to their templates if future dogfood reveals
similar drift.

**Why this design over 15 standalone templates:** view and artifact
have largely independent dimensions for 4 of 5 artifact types. The
view carries the pedagogical *purpose* (who's listening, what they
must learn) and the artifact carries the medium *format* (how long,
how dense, what structure). The 12 view-cycled cells share patterns
along both axes; maintaining them as 8 composable files instead of
12 monoliths is DRY-er and easier to evolve. The
interaction-overrides table handles the minority of cells where the
joint effect surprises. Mind_map's view-blindness (an empirical
finding) is handled by structural simplification rather than ever-
escalating prompt steering.

### Failsafe semantics

Before composing each artifact's `focus_prompt` (for the 4
view-cycled types), verify the loaded view-prefix template against
this checklist:

1. All five `## §<N>` headers are present, in order, with the
   exact slugs: §1 Pedagogical purpose / §2 Audience profile /
   §3 Style mandate / §4 Anti-patterns / §5 Success criteria.
2. Each of those five sections has at least one non-blank
   body line (i.e., the heading is followed by substantive
   content, not just whitespace before the next heading).

If either check fails, abort the whole skill — the View-Purpose
Preservation principle (the reason this skill produces tier-faithful
artifacts rather than generic ones) breaks down if the view-prefix
is incomplete or stubbed. Tell the user which view template is
broken, which check failed, and where to fix it before retrying.

The failsafe runs once per artifact (not just once per session)
because the 13-artifact loop is long-running, and a template change
mid-session (e.g., the user editing a view file in another window)
should be detected, not silently ignored. The cost is negligible —
re-reading a ~120-line template is cheap.

The mind_map composition does not need the failsafe (no view-prefix
loaded).
