# mp-flow-intake

新需求或原意实质修订先按[INTENT 规范](../../../docs/rule/[STANDARD]_AI_Engineering_Intent.md)选择唯一独立正本或 Issue 原意区，复用清楚来源与同范围决定；分开原意核对、内容接受、状态和操作授权，完整基线可恢复。未知保持未知；缺决定只停依赖部分，不重复形式访谈。

识别目标、范围、验收、目标分支、版本影响与风险，复用用户已有计划/真实接受。按[文档框架](../../../docs/rule/[STANDARD]_Documentation_Framework.md)判断持续维护需要，先找稳定任务 INDEX 与主 Issue，复用原目录；小任务用 Issue/PR。按[执行规范](../../../docs/rule/[STANDARD]_AI_Engineering_Execution_HITL_Prompt.md)记录目标/对象/环境/权限/风险五授权边界，未实质变化就复用，Owner 只处理必要信息、实质决定和最终接受。拆分任务用单 Epic/单活动主 PR/多子 PR，先查实际规则和权限；输出边界、验证矩阵、未决项后继续隔离 worktree 实施。

在已有授权范围内由代理执行操作，owner 负责未决事项。需要决定时给出 2–3 个选项、影响及有理由的推荐；必须等待的决定等待答复，推荐不构成批准。详见 [执行与决策规范](../../../docs/rule/[STANDARD]_AI_Engineering_Execution_HITL_Prompt.md)。
