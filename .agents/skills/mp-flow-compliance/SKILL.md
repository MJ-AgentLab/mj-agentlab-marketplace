# mp-flow-compliance

运行 npm run validate 检查市场、各 portable manifest、公开和开发技能的 YAML、名称/描述预算、资源路径和当前文档。核对候选精确三插件、五公开技能、两个显式学习策略和 20 个开发技能；Learning Evidence 共用脚本属于包内，过渡目录不再存在，旧 Understanding 未注册。运行受影响的有行为意义的测试；实际 Python 与安装缓存执行不能用静态扫描代替，保存测试明确隔离库、GitHub 写入使用替身。A6 触发集合以 scripts/check-a6.mjs 为准，更新根 AGENTS.md。按 [验收账本](../../../docs/runbook/[RUNBOOK]_Learning_Evidence_Kit_Acceptance.md)区分结构、合成角色、客户端和窗口证据；所有启用入口严格待答，原生持续显示缺证据或失败则延期。输出错误、已验证项和限制，修复后重跑受影响检查。

在已有授权范围内由代理执行操作，owner 负责未决事项。需要决定时给出 2–3 个选项、影响及有理由的推荐；必须等待的决定等待答复，推荐不构成批准。详见 [执行与决策规范](../../../docs/rule/[STANDARD]_AI_Engineering_Execution_HITL_Prompt.md)。

解释技能的展示入口、自然路由和包内资源必须一致，验收依据见 [记录](../../../docs/runbook/[RUNBOOK]_Explain_Kit_Acceptance.md)。

新增插件、仓库主标或图标修改时使用 [mp-design-icon](../mp-design-icon/SKILL.md)，读取品牌规范、复用已有批准并核对候选选择及实际尺寸预览。
