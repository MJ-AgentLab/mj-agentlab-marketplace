# mp-flow-plan

需求承接按[INTENT 规范](../../../docs/rule/[STANDARD]_AI_Engineering_Intent.md)引用唯一原意与完整接受基线，逐项映射承担范围、验收、依赖及交付/支撑/背景关系；共享 Issue 分原意映射。实质修订保留旧接受及受影响范围，材料不足只阻依赖部分，不将计划进度复制回 INTENT。

先读[文档框架](../../../docs/rule/[STANDARD]_Documentation_Framework.md)和已有任务 INDEX，以真实范围/接受基线组织顺序、依赖、验证、风险与恢复。需跨会话、多 PR、独立验收或交接时复用稳定 plans/<任务>/，用 TASK_INDEX/PLAN 模板建立薄入口和唯一主 PLAN；实际结果后再开唯一 REPORT。准入、评估、决定与接受基线优先有界章节，长期技术决定由 ADR 承载。已有计划直接细化，新确认/失败/恢复/批次追加，冻结接受内容保留版本/原件。明确接受在范围内生效，同交付同步 canonical；已授权的阶段切换/修复不重复请批。拆分任务按[执行规范](../../../docs/rule/[STANDARD]_AI_Engineering_Execution_HITL_Prompt.md)用单 Epic、单活动主 PR 与内部子 PR，分别设计实际候选 Harness 与最终保护门禁；实质未决项给选项，同时推进独立工作。

在已有授权范围内由代理执行操作，owner 负责未决事项。需要决定时给出 2–3 个选项、影响及有理由的推荐；必须等待的决定等待答复，推荐不构成批准。详见 [执行与决策规范](../../../docs/rule/[STANDARD]_AI_Engineering_Execution_HITL_Prompt.md)。

新增插件、仓库主标或图标修改时使用 [mp-design-icon](../mp-design-icon/SKILL.md)，读取品牌规范、复用已有批准并核对候选选择及实际尺寸预览。
