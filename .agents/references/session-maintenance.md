# 会话维护规则

本规则由根 [AGENTS.md](../../AGENTS.md) 按需引入。

## 触发与输出

- “总结归档本次对话”“归档本次对话”“整理本次 session”等明确请求：输出一个标题和精简摘要，使用下方归档模板。
- “推荐当前对话标题”“给本次对话命名”等：只输出一个推荐标题，不附说明或候选列表。
- “将当前任务重命名为……”等明确改名请求：按用户指定的完整标题原文执行，不添加日期、编号或改写内容。
- “按项目规范重命名当前任务”等：按下方标题和日期规则生成一个标题，并执行重命名。

引用、示例、否定、机制讨论或询问可行性不触发。“PR 合并后收尾”“归档文件”等按实际对象处理；对象不明且影响动作时再澄清。实施或修改本机制的请求及其中示例，不属于实际归档或重命名请求。

## 标题与日期

以下生成规则适用于归档标题、推荐标题和按项目规范生成的重命名标题；用户指定完整标题时保留原文。

| 已确认关联 | 标题格式 |
|---|---|
| Issue 和 PR | `MMDD-I编号-P编号-对象任务` |
| 仅 Issue | `MMDD-I编号-对象任务` |
| 仅 PR | `MMDD-P编号-对象任务` |
| 两者均无 | `MMDD-对象任务` |

只使用本次对话中已明确或已核实属于本仓库、本任务的编号，不搜索或创建 Issue、PR 来补齐。最多保留一个主要 Issue 和一个主要 PR；主要关联不明确时省略，其他必要关联写入正文。编号不代表已关闭、已合并或已完成。

对象任务采用“核心对象＋具体动作”的简短中文描述，优先 6–10 个汉字，保留必要技术缩写，以清楚辨识为先；长度是建议，不机械截断。不添加分类、阶段或完成状态。

用户指定日期或时区优先，否则采用当前会话明确时区，缺省 Asia/Taipei。标题日期用 MMDD，记录日期用 YYYY-MM-DD；跨日会话按归档或命名当天计算，不改写历史成果日期或自动重命名旧对话。

## 归档模板

```text
标题：按上述规则生成
日期：YYYY-MM-DD

成果：实际完成了什么，以及必要的验证结果。
结论：本次确定了什么。
待办：尚未完成的事项，以及下一步从哪里继续。
```

成果、结论、待办各用一至三句话，无内容写“无”“尚未形成”或“暂无明确后续动作”。不添加前言、重复结语、关键词或其他固定元信息。

## 事实与继续工作信息

只依据本次可获取的对话和已核实成果，区分讨论、计划、接受、写入、测试、提交、合并与部署；不将计划写成已完成成果，不将静态检查通过写成业务运行成功，不计入其他任务的成果。

仅在影响继续工作时，保留工作树、分支、未提交修改、相关文件、目标环境、首个未完成步骤、已有授权范围及恢复条件。发生过实际操作时，必要的复位状态和在途任务不能省略；不包含凭据或未脱敏工具输出，不另建交接流程。

必要时注明验证对应的 SHA、环境、批次或时点；不为填模板重跑测试或查询服务。上下文不全时，在末尾简短说明覆盖范围。

## 动作与结果

普通归档和推荐标题默认只回复文字，不保存或移动文件、不执行 Git 或运维动作、不修改客户端标题或归档客户端任务。原任务已有的记录义务继续适用。

明确重命名请求即为该动作的授权，目标和标题已明确或已要求按规范生成时，不重复确认：

1. 确定目标与最终标题。当前任务使用工具的当前任务语义，不猜任务 ID；其他任务仅在用户明确指定且已核实目标时操作。
2. 调用本次实际可用的客户端重命名功能。若提供 `mcp__codex_app__set_thread_title`，传入 `title`；修改当前任务时省略 `threadId`。工具名称及参数以本次实际接口为准。
3. 检查返回是否确认目标标题已修改，成功确认后才报告“已重命名”及实际标题。失败或结果不明时不报成功；结果不确定时优先只读核实，不盲目重复操作。
4. 功能不可用、失败或仍无法确认时，如实说明“未执行”“失败”或“结果未确认”，并提供手动标题；用户指定的完整标题仍保持原文。

额外保存文件或客户端归档按用户明确请求、目标、已有授权及实际工具能力处理，并分别核实结果。推荐标题不等于已改名，文字摘要不等于已保存，生成归档记录不等于客户端任务已归档。

验证本机制时，静态规则检查与实际客户端操作分别记录；实际重命名仅针对明确授权的测试任务，工具接口存在或静态场景通过不能证明修改成功。
