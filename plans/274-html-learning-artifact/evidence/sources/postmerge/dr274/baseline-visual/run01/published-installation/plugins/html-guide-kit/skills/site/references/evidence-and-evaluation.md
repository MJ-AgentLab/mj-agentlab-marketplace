# Evidence and Evaluation

制作记录可与交接记录合并，至少保存：确认范围、材料/工具版本、文件清单与哈希、实际检查命令/方法/动作/输出、失败和重跑、未查范围、Sites真实身份/保存版本/部署状态/地址/访问范围。来源支持、内容核验、工具通过与任务完成分别判断。

上线前最小四门槛：

1. **Installation and Local Independence**：入口可发现调用，包内闭合且缓存资源与源字节一致；从独立消费目录运行，不读取研究目录或其他缓存。
2. **Core Content Correctness**：代表材料的关键结论、条件、例外、关系和答案判准独立对照原件，英文核心/中文活动及术语一致。自动检查不替语义核验。
3. **Sites Main Flow**：一个目标客户端从材料到六步制作和真实发布，核对地址、保存版本、精确源码、部署状态与访问范围。Sites不可用是核心门槛缺口。
4. **Engineering and Release Boundary**：适用仓库门禁/安装/许可通过，无凭据或非预期材料。合成角色不代作 GitHub 独立批准或 Owner 接受。

独立合成验收记录角色与实际 Agent、候选SHA/资源版本、输入/动作/输出、判准和结论。检查失败先修复，保留旧FAIL与新身份重跑。核心、全计划、插件发布、网页部署及Owner体检各有实际证据后分别报告。

第二客户端、完整原生窗口/视觉/可访问性及扩展场景可后移，记录影响、负责角色和恢复条件；延期不能写PASS。必要答案缺失仍严格待答，未测窗口持续显示不以文字pending替代。

上线后 Owner 体检聚焦真实制作流程、阅读/操作和异常/扩展场景；仅针对实际问题修订并复验受影响部分。未取得体检或接受时保持开放。

学习者效果需要另定人群、任务、条件、问题和判准，并保留原始回答/误解/限制、负结果及不确定性。比较交互与静态时尽量固定内容、题目、信息和测量，说明顺序/熟悉度等混杂。美观、喜好、操作正常或单次答对不证明改善。未开展测量时 **Understanding Effects: NOT_MEASURED**；不阻本次最小上线，但不得扩张效果声明。

恢复：本地输出可从明确材料再生；发布问题停止新增升级，回读当前身份/受众与版本，使用已知良好保存版本或前向修复。报告恢复对象及复验范围，不删除发布历史。
