# Six-Step Workflow

本方法是 HTML Learning Artifact Execution Guide 的原创本地提炼，状态为 **Working Model**；来源固定字节见 resource-provenance.json。方法可指导制作，不能证明理解效果。

| 阶段 | 必须形成的内容 | 检查与返回条件 |
|---|---|---|
| Define Understanding Needs — 理解需求 | Audience 背景/假设、Task 情境与行动、Understanding Goals 可展示能力、材料边界、Observable Questions 与 Answer Criteria（是否允许回查/提示/重试） | 每个关键答案有材料依据；缺口影响判断时补材料或收窄目标 |
| Develop Learning Materials — 学习材料 | 可独立阅读的 Markdown、必要基础、关系、条件、例外、案例/反例、局部及综合练习、术语和来源定位 | 按目标核对覆盖；KU 可用于追溯，不以数量代替完整性；保原技术标识、数字、单位与否定范围 |
| Design Information Structure and Relationship Representation — 结构与关系 | 分组、层级、阅读顺序、比较维度、静态草图、关系说明 | 分类不画成流程，相关不画成因果；位置/线/箭头/颜色含义有依据；比较可同时查看，失真返回材料阶段 |
| Design Interaction and UI/UX — 交互和界面 | 每项交互的理解用途、输入、变化、反馈、异常、恢复、静态替代 | 无明确用途采用静态；模型公开规则/参数/假设/边界；检查键盘、焦点、窄屏与减少动效 |
| Build and Verify HTML through Sites — 制作核验 | 有界交接包、本地网页/材料、实际检查记录、Sites精确源状态/保存版本/部署结果 | 先静态后交互；按失败原因回第2–4步；跳过/未检查不算通过 |
| Evaluate and Revise — 评价修订 | 真实 Owner 体检、修订及受影响复验；需要时另做学习者表现评价 | 核对题目/答案独立性，保留负结果与不确定性；操作成功不推定理解改善 |

候选教材结构为 **Overview → Necessary Foundations → Topic Explanation and Local Practice → Integrated Practice**，邻近给出中文解释。按具体主题选结构；专用基础就地解释，熟悉者可跳过基础，章节与交互数量不固定。

每条重要主张保留：主张和条件、对应展示、来源/构造边界、检查问题。Exhibit 是对应展示，Evidence 是支持主张的证据，两者不自动等同。内容、视图与检查记录分别保存。来源矛盾保留双方与影响；无法可靠判断时提供有界参考并说明缺口。

第1步同时定义判准，第3–4步已介入可访问性；第2–4步允许反复。每步可用同一短记录承载，完成条件是所需信息齐备，不要求建空文件或把所有内部检查变成学习者可见栏目。
