# Interaction and Recovery

交互先说明支持哪个理解问题。对每项选用的活动记录：操作前信息、输入、变化、结果、反馈依据、异常、恢复及静态替代。静态已足够时采用静态形式；比较信息保持同时可见。

| 用途 | 合适形式及边界 |
|---|---|
| 找到条件/例外 | 邻近说明及原生 details；必要结论常显，展开不是获得关键条件的唯一方式 |
| 检查判断与理由 | 题目、选项或开放解释与来源回链；有可靠判准才核对，否则给有界参考，不评分 |
| 探索规则 | 可调整输入与公开规则/假设；变化及时显示，不把构造结果写成真实因果证据 |
| 关联内容 | 相关高亮/回链伴随可读文字，不只靠颜色；图解说明线条和位置的含义 |
| 回流意见 | 本地导出版本、目标/活动编号、明确回答、核对状态、尝试和意见；不收集无用途个人数据 |

包内 choice 是有界参考组件。默认未操作与未提交分别保留；用户明确选择后点击核对才产生判断。改答立即使旧核对失效，核对结果绑定当次输入；重新开始清空回答/结果并保持合理焦点。参考解释及来源在静态路径也可取得。页面活动不充当 Owner 审批窗口。

复制只有剪贴板 API 实际成功后显示成功；拒绝/不可用时说明失败，提供可选择的手动文本及明确关闭路径，返回原控件焦点。不把选中文本或自动预选当复制成功。导出使用本地文件，包含实际状态与制品版本，不宣称学习完成。

采用语义标题、可辨识表头、原生按钮/表单、关联标签与状态；键盘检查进入、操作、离开、返回，分别看焦点位置和操作结果。窄屏重排、可见焦点、颜色独立性、减少动效和静态替代是设计要求；少量检查不能称全面 WCAG 合规。
