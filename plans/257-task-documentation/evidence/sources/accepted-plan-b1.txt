## 原意与接受来源

Owner 希望管理者从任务入口找到目标、进度、缺口、下一操作与责任；产品人员区分原意、接受范围、需求变化与实现；开发/运维同时找到执行链和现行技术规范。来源为本聊天 2026-10-18 的任务、逐项选项答复、设计理解确认、七原则及开始实施授权。以下是本次接受内容的可版本化捕获，不冒充原始聊天导出或 GitHub 非作者批准。

## 接受基线 B1

1. canonical 维护长期唯一正本；working 维护任务计划、真实决定、接受基线、实施和验证。层次与 type/state/批准/任务完成分开；draft SPEC 仍 canonical，完成 REPORT 仍 working。
2. 稳定领域位置不批量搬迁；任务使用 plans/<既有Issue与主题或稳定主题>/，薄 INDEX + 主 PLAN + 主 REPORT + 必要脱敏 evidence。目录不随 PR、会话、批次或完成而搬迁。公共台账、复盘和长期问题留公共/领域位置，按用途与维护责任判断。
3. 仅新增 PLAN/REPORT 类型；评估、任务决定和接受基线先复用主文档章节，长期决定仍用 ADR。持续维护任务按需启用，小改复用 Issue/PR；不为建目录强制建 Issue。
4. 主 Issue/Epic 是进度正本；薄入口允许带日期/具体来源的阶段、缺口、下一步、责任快照，过期以 Issue 为准。PLAN 管如何执行，REPORT 管实际事实，出现实际结果后开始 REPORT。
5. 原八字段 + layer；任务材料有稳定任务关联及跟踪入口。新文档严格，旧文档明确兼容、实质修订/选中迁移时审定；不按 docs 路径或类型推断层次，原生格式/冻结来源保持。
6. PLAN 可修订而接受历史不可覆盖；保留完整范围、判准、决定原文/来源/时间/适用范围，版本或可恢复快照绑定。明确批准在范围内生效，交付完成前同步受影响 canonical；普通排程/修复/重跑由 Agent 判断。
7. 原始输入、接受、实施和验证分别关联。失败/拒绝/超时/阻断/修复重跑留痕，勘误追加；hash 不代替原件。Git历史、HTML封存/plan.json和运行闭包保持原义；凭据/环境文件/受限备份不进普通集合。
8. 先规范/模板/技能/Harness、镜像/夹具/索引/来源依赖适配，再以 HTML Epic #217 的 PR1 稳定交付链作有界试行。旧 ADR/SPEC/GUIDE/验收与封存保持，不把事后重建当原计划，不追溯改写旧 PR 拓扑。资源校验与阅读/交接分别验收。
9. 试行后提出新任务推广和旧任务选择性迁移，由 Owner 决定范围。核心交付、整个计划完成和 Owner 最终接受分别记录。

## 七项执行原则与授权 A1

- Agent 执行，Owner 决策：Agent 承担技术操作；Owner 只补必要信息、作实质决定与授权，默认从成品结果验收，不参与常规构建审查。
- 独立合成验收：Agent 模拟相关角色并独立核验功能/工程质量，证据可复现；不要求真人模拟，不替代 Owner 最终接受或受保护分支的真实非作者批准。
- 严格窗口，分段交付：未提交、默认、预选、超时、关闭非回答；窗口持续显示须实证，不承诺锁宿主。非核心缺失延期对应入口，核心自身验收后可先交付，延期不视为通过，写明影响/责任/恢复条件。
- 集中授权，条件复用：目标、对象、环境、权限和风险边界未实质变化时复用，越界再授权。
- 可执行约束，证据驱动：Harness 自动必要门禁；Agent 自验修复，证据不足不通过，不静默放宽冻结判准。
- 风险隔离，可控恢复：不越技术权限；不可逆满足专门控制，已发布变更具备按风险的监控、责任及恢复能力。
- 单 Epic、单活动主 PR、多子 PR：子 PR 的 base 是任务集成分支（主 PR head），内部路径不保护，Agent 验证后合并；主 PR→受保护 develop，保留真实保护门禁。每 Epic 同时仅一活动主 PR；合入后延期留原 Epic，获准恢复另建下一批主 PR并绑定新基线。

Owner 最新明确授权：现在可以修改文件，按最终方案开始实施，使用独立 worktree，按单 Epic/单活动主 PR/多子 PR推进，先适配后 HTML PR1试行；已有授权内自主执行，实质决定再提选项。

目标为 origin/develop a2a57d1（完整 SHA 由执行记录绑定），工作区为独立 codex/task-documentation。原 develop 用户改动不动。市场/五插件运行版本和运行内容不变；无正式发布授权，无保护绕过、改 ruleset、批量历史迁移或真实模型/桌面重测。

## 执行顺序与验证

1. 建立本入口/基线/主 PR；记录实际仓库保护、远端与工作区。
2. 子 PR A：新 ADR、框架/执行规范历史保存、PLAN/REPORT/任务入口模板、技能和索引/A6。
3. 子 PR B：分层/兼容/任务导航/来源校验、隔离复制、夹具与内部 PR Harness；实质反例、npm test/validate/基线工具/真实隔离安装Python。
4. A/B通过并集成后子 PR C：HTML PR1只读来源映射、资源核对和独立角色阅读/交接试行，保留缺证/失败与历史。
5. 主 PR 全量集成复验、当前保护门禁；Owner 最终接受独立等待，不指定审查人。

## 风险与恢复

旧混合RUNBOOK不自动分类，使用明确兼容范围；已有 plan/communication-kit 冻结内容保留。子 PR 检查目标是实际合并候选树，最终主 PR 不能因内部通过而跳保护。修复在隔离分支进行；必要时通过新提交撤回本次变化，不覆盖发布或删除历史。主 Issue/REPORT记录所有未执行、延期、失败和Owner接受状态。
