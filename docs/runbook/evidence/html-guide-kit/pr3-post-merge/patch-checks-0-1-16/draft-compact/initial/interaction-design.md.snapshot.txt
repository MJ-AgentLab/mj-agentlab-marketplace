# 交互设计

本参考只描述教学交互，不实现或操作教材。先完整读取[指南框架](guide-framework.md)，继承其读取证据、目标确认、完整源规则、归因和输出边界；这里补充操作、反馈和恢复方法。结构随已确认问题和材料调整，不是必须覆盖的控件或课时清单。

## 1. 交互说明与模式

每项采用的交互写清：理解用途及材料依据；起始信息与当前状态、未知及限制；读者明确操作或触发；变化的内容及仍可见的条件；局部结果属于模拟、参考还是有据判断；反馈解释理由、缺项、依据及边界；恢复如何改选、重试、回退、复位及使旧反馈失效。可用短段或表格，不强制形式。只有交互帮助当前问题且收益值得成本才采用，静态文字、条件表和并列说明也可完整交付。

可选模式按用途选择：

- 展开 Disclosure：低频细节，入口有意义、保留上下文；需比较可多项同时可见，结论和关键限制常显。
- 切换 View switching：当前不需并列的独立视图，标当前视图、变化范围及返回；比较优先并列，不靠记住另一屏。
- 关联高亮 Linked highlighting：核对原文已有对应，用文字关系标签、取消选择及非颜色提示，不制造关联。
- 筛选 Filtering：找相关子集，显示条件、结果范围、隐藏内容和清除；不无声过滤关键例外。
- 分步 Step-through：观察有据过程或状态，保留全局、当前位置及触发，允许暂停、前进、回退、重置；无过程依据不造步骤。
- 条件模拟 Condition simulation：探索源规则在不同输入下的结果，按规则完整性限定，不当真实动作或因果验证。
- 教学自检 Learning check：练习解释规则、关系和边界，按可靠判准分反馈与参考，不自动评能力。

重要视觉配等价文字，必要信息不只靠颜色、悬停、动画。操作名称、状态、反馈清楚，考虑键盘、焦点、缩放和窄屏；只提出设计及待检查范围，不称已通过访问或操作验证。

## 2. 演示与恢复

尽量同组明确材料贯穿必要步骤，不频繁换情境。每步给当前事实、单个操作或触发、变化、局部结果、限制和来源；保留分支、循环、暂停、退出及例外，不强画单线。源需要人为触发时，条件满足或参数改变只更新可执行判断，不能显示动作已发生、成功或业务通过。提交、确认、恢复等都标为教学模拟，不向外部执行。

操作结果使用框架的完整源规则及明示覆盖范围，不自由压缩概览、图示补充、例子、反馈或核对项的前提。恢复含全部源动作、对象和明确字段，不仅初值；小图只示部分时标局部并引导完整恢复。回退说回到哪一态、保留或清除什么，重置说全部恢复和清除对象；不能保证现实系统恢复到最后成功态或具有同名控件。

新增界面状态、默认值、输入保留、选中项、高亮、提示、旧反馈清除或失效，与源结果分列并就地标设计、理由及局部范围；源没写不推其变化或不变。整页构造、情境进入或重试说明不足以标注具体操作结果。源启发设计不等于规范依据，设计标签也不抵消后句的错误源归因。恢复、反馈、答案和作者清单同样回查。

## 3. 条件模拟边界

先核对变量、值域、必要当前状态、前提、触发、分支结果、优先、例外、范围和定位，再决定哪些输入可判定：

- 完整规则覆盖所选输入：展开必要组合、边界和例外，每个结果给理由、依据及范围。
- 部分分支：只判已覆盖部分，其他显示材料未规定及具体缺项，不自动拒绝全部已知内容。
- 阈值、范围、触发者或结果缺失：保留缺口，不默认数值或自动动作，可说明它阻断什么判断。
- 来源冲突且无适用优先：并列来源，不能选方便的结果或伪造唯一规则。
- 另加教学假设：单列构造或假设模型和范围，输出不当原规则、现实事实或消除源冲突的证据。

规则完整与输入有效分开：源明定允许域时，越界标超出本模拟范围，不混入正常分支；域未定义不发明域、不宣布具体值无效。已命中局部源规则及全部必要前提的输入仍判已知结果；流程可达性质不定义完整输入域。额外集合、类型或上下界，只能就地标为本互动的构造或设计，在起始信息、选项和反馈一致；另一处正确标签不补本处遗漏。

只用原文的必要条件、排他范围或禁止规则作确定否定；仅规定一态结果不等于其他态禁止，也不保证未覆盖分支保持值。先固定当前态与单个直接操作，核对所有宽规则、排除、恢复和例外；别操作前提不套用，名称相近的状态不代换。不可用反例不得误排除源允许状态；内部冲突回查源，规则不足保持待定，不靠惯例。先经别操作改态的路径缺规则，不撤销当前已知直接结果；不同操作及路径分别判断。

纯条件组合不附操作或字段结果时，可独立判断，不强加源不存在的业务状态；一旦附结果，须完整当前态和操作前提。“且”有任一明确不满足即不满足，另一项未知不撤销；“或”有任一明确满足即满足，另一项未知不撤销。其余含未知组合才待定，全已知按源判。未知是信息不足，不新增业务取值；组合成立不证明整体操作可执行或已发生，也不决定其他字段。

## 4. 生命周期与反馈

先说进入、当前态与输入来源、继续、改条件、重试、退出和复位关系，再写分支反馈。共享连续模拟首步用初值，以后每步取最新状态、固定单个操作重匹配源规则；改条件不是复位。独立固定情境每次进入或重试明确恢复必要题设及依据、范围，不靠初次面板默补。先说明反馈是共享状态还是独立题设，不暗示继承上一情境。

每个反馈块在标题、表首或紧邻处明示共同前提及覆盖全部哪些分支；否则每支写足必要当前态、输入、操作。前行、旁表、前例、初始面板不自动供给前提。范围外查其他源规则，不满足本块前提不自动等于禁止、值保持或全部未知。源未述字段不补变化、保持或清除，已有局部结果保留；依赖未决状态的后续路径待定，可返回明确题设或有据恢复再继续，不静默把未知操作当完成或未发生。

重复尝试按最新态和源条件判断。仍满足同一允许条件且无明确限次或重复例外时，保留源结果，不添“当前值必须有效、只能一次”等前提；赋值与当前值相同仍有确定结果及变化量。重复意义、提示或特殊界面反馈缺失，只保留该缺口，不抹掉已知操作和状态数值。排他须框架要求的原文明示或完整局部枚举支持，含恢复和例外，并就地限范围。

操作分支互斥或明示优先；累计原因反馈另列清单，说明同时合并所有适用项。逐对检查“任意、其他、任一未知”等宽行是否覆盖已决定的具体组合，不能第一匹配就漏已知缺项、未知说明或累计结果。全文文字、边界、自检、恢复用同一合并规则。覆盖难写清时选独立固定情境，明示必要题设、适用分支、每次复位及局部假设，不借情境填造源规则或删已知结论。

示例结果同时给当前输入、命中规则或未覆盖分支、局部结果、限制、理由和恢复；反馈帮助解释为何成立、缺什么及常见误区，不仅列控件名。源条件满足不自动变成验证成功、动作完成或真实业务通过；模拟、构造、设计、已核验主张分别标明。

## 5. 教学自检

自检仅是指南中的设计，不在聊天自动开测验。每题对应已确认问题，列材料依据、确定反馈所需当前态、输入、假设和范围，只列相关字段。共享默认明示覆盖哪些题及如何被题设覆盖；题名、初始面板、前例或别题不自动供给条件。可标明局部题设假设；源规则足够时只在该假设内判定，不把假设当事实或补造规则。前提仍缺就给条件化参考或待补，不给唯一答案。

可靠判准须明确适用材料支持、有可核对结果；多种答案可成立就容纳，不为单选造唯一。提交后反馈局部判断、理由、误区、来源和限制，并允许改答、重试、重做及回看材料。没有可靠判准，如缺定义规则、冲突、开放取舍或缺情境，只给有边界参考：假设、可成立思路、待核验因素及尚不能判断的部分；不伪造标准答案或自动判对错，不将未评自由文本当核验。

题目不预选或推荐正确答案，目标推荐不迁移成答题提示。空答、无效答复、沉默、超时、关闭不推进或当知识错误，保持待答。修改答案后旧判断清除或明确失效，重新提交按当前答案反馈；重做说明清除哪些选择和反馈、复位何种题设及如何返回材料。题干、判准、理由、误区与重试使用同一前提，旁处正确源条件不补本题遗漏。

可用已核对、已提交等局部状态，不出总分、能力等级、绩效或长期掌握结论。一次答对、全操作完成、信心、点击意愿或提示后改答，仅支持相应当次事实；反馈后练习不追写此前已掌握。

## 6. 全篇核对

逐处检查实际采用的交互：服务确认目标；主张、动作、对象及全部源明定字段结果有据；关键条件、例外、未知、来源及比较内容可见；操作前提与生命周期一致；完整与缺失规则、可靠与不可靠判准分开；反馈有理由、误区和恢复。重点核对允许、不可、只能、未规定及数量关系，概览、图示、表格、恢复、自检、附录和编写者清单同样检查，旁处正确不抵消本处错误。

交互示例、拒绝和引用只用自然语言保义与定位，不重印 HTML、代码、伪代码、图形语言或制作命令，不写具体工具、配置、文件结构或制作发布步骤。后续可以拟检查新情境解释、遗漏、来源、无效操作和往返查找；未执行就称拟检查或待检查。设计、模拟、局部自检和静态审查都不证明目标用户理解改善、稳定掌握或全面可访问性合规。
