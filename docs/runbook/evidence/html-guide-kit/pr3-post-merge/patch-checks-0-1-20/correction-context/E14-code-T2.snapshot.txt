# 《普通材料包领取流程》交互教材绘制指南

## 一、确认的教学目标

### 读者

负责培训现场工作人员的讲解者。读者已了解活动和普通材料包的基本用途，需要形成一致、可核对的流程讲解。

### 使用任务

从规定的初始状态出发，说明一名访客如何完成核验、领取和归还，并正确处理以下分支：

- 预约或导览条件缺失；
- 库存为零；
- 领取前取消预约；
- 使用教学演示的“重新开始”。

### 理解问题

读者完成教材后，应能依据材料说明：

1. 正常领取路径需要哪些前提和操作？
2. 条件缺失时，核验状态和反馈如何变化？
3. 库存不足时，访客状态与库存分别如何处理？
4. 取消和“重新开始”在触发条件、影响字段及适用范围上有什么差异？

这里的“完成教材”只表示完成本次查看或练习，不证明读者已经稳定掌握规则。

## 二、材料范围与依据

### 原材料

- 名称：《活动材料包领取说明》
- 版本：修订 1
- 定位方式：§1–§8
- 已读范围：全文
- 性质：本次虚构活动规则

### 已核验背景

无。本指南不引入外部制度、产品行为或现实系统功能。

### 教学构造

为呈现规则而设置的面板布局、操作入口、当前步骤、选择状态、提示、反馈和练习情境，均属于教学构造，不是原材料规定的现实界面。

### 设计判断

采用“完整规则常显＋同一访客分步演示＋独立分支练习”的组织方式。理由是材料同时包含状态变化、条件分支、库存变化以及不同恢复行为；保持同一情境有助于读者比较每次操作前后的差异。

### 不得扩展的范围

依据原材料 §1、§7、§8：

- 只讲普通材料包；
- 当前只处理一名访客；
- 工作人员试用证不在适用范围；
- 不推导多人并发规则；
- 不推导预约时效；
- 不推导跨活动规则；
- “重新开始”是教学演示规定的恢复方式，不表示现实系统必须具有同名控件；
- “已核验”不等于“已领取”，也不保证库存充足。

## 三、全篇共同规则

以下规则应在首次演示任何操作结果之前完整呈现，并明确说明它们适用于教材的概览、演示、分支案例、反馈、恢复说明和教学自检。

### 1. 初始状态

依据原材料 §1：

- 适用对象：一名访客；
- 材料包类型：普通材料包；
- 库存：2；
- 访客状态：“未核验”；
- 预约：“无效”；
- 导览：“未完成”。

工作人员试用证不在本说明适用范围。

### 2. 领取资格条件

依据原材料 §2：

- 必须同时满足“预约有效”和“导览完成”，才具备核验通过的条件；
- 两项条件缺一不可；
- 体验通行证只允许观察；
- 体验通行证不能替代预约；
- 体验通行证不能替代导览。

材料没有规定如何取得有效预约或如何完成导览。因此，教材可以将两项值作为演示输入，但必须标明这是教学情境设置，不得虚构现实办理步骤。

### 3. 核验规则

依据原材料 §3：

当前状态为“未核验”并操作“核验”时：

- 若预约有效且导览完成，访客状态变为“已核验”；
- 若任一条件不满足，访客状态保留为“未核验”；
- 条件不满足时，应指出缺少哪一项条件；
- 核验不改变库存。

原材料只明确规定了在“未核验”状态操作“核验”的结果。对其他状态再次操作“核验”的结果没有规定，教材应标为“材料未覆盖”，不得自行设为允许、禁止、无变化或重新核验。

### 4. 领取规则

依据原材料 §4：

- 只有“已核验”状态可以操作“领取”；
- 在“已核验”且库存大于 0 时，访客状态变为“已领取”，库存减少 1；
- 在“已核验”且库存为 0 时，显示“等待补充”，访客状态保留为“已核验”，库存不变；
- 其他状态不可领取。

“等待补充”是原材料规定的显示结果，不应被改写成已经排队、已经补货或保证稍后可以领取。

### 5. 归还规则

依据原材料 §5：

- 只有“已领取”状态可以操作“归还”；
- 归还后，访客状态变为“已归还”；
- 归还后，库存增加 1；
- 其他状态不可归还。

材料没有说明“已归还”后是否可以再次核验、领取或归还。除已明确的不可归还规则外，其他未规定操作应分别标为“材料未覆盖”。

### 6. 取消规则

依据原材料 §6：

- 领取前可以取消预约；
- 取消后，预约改为“无效”；
- 取消后，访客状态回到“未核验”；
- 取消不改变导览完成情况；
- 取消不改变库存；
- 在“已领取”或“已归还”状态，取消不可用。

“领取前”至少覆盖材料明确允许取消且尚未进入“已领取”或“已归还”的情境。教材不应自行增加取消原因、时限或外部后果。

### 7. 重新开始规则

依据原材料 §7：

- “重新开始”专为教学演示设置；
- 操作后清除本轮操作；
- 恢复 §1 的全部初始值，即库存 2、状态“未核验”、预约“无效”、导览“未完成”；
- 该规则不表示现实系统必须提供同名控件。

“清除本轮操作”来自原材料，但原材料没有定义现实日志、历史记录或外部数据。教材不得将其扩展为删除业务记录。

## 四、整体呈现结构

建议使用单页纵向教材，分为四个连续区域。

### 区域一：范围与核心结论

常显以下信息：

- 这是单名访客领取普通材料包的虚构规则；
- 有效预约和已完成导览缺一不可；
- 核验通过不等于已经领取；
- 是否能够实际领取还取决于库存；
- 多人并发、预约时效和跨活动规则不在材料范围内。

核心限制不可隐藏在展开项、悬停内容或完成演示后才出现。

### 区域二：完整规则卡

按“核验、领取、归还、取消、重新开始”分组展示第三部分的完整规则。

每组同时展示：

- 必要当前状态；
- 操作名称；
- 条件；
- 状态结果；
- 库存结果；
- 其他明确字段结果；
- 不可用情况；
- 未覆盖事项；
- 原材料定位。

不得只显示成功路径。

### 区域三：分步演示

使用同一名虚构访客贯穿正常路径。访客姓名如需出现，须标为教学构造，不得暗示来自活动记录。

演示中持续显示：

- 当前访客状态；
- 当前预约状态；
- 当前导览状态；
- 当前库存；
- 当前步骤；
- 最近一次反馈及其依据。

### 区域四：分支练习与自检

用独立题设呈现：

- 条件缺失；
- 库存为零；
- 取消预约；
- “重新开始”与取消的区别。

每个题设都应明确自己的初始状态，不继承上一题的操作结果。

## 五、正常流程的分步演示

### 第一步：查看初始状态

显示原材料 §1 的全部初始值：

- 状态“未核验”；
- 预约“无效”；
- 导览“未完成”；
- 库存 2。

教学提示说明：此时不能直接领取，因为只有“已核验”状态可以领取，依据原材料 §4。

若教材允许读者尝试“领取”，反馈应为：

- 判断：不可领取；
- 理由：当前状态为“未核验”，而领取仅适用于“已核验”状态；
- 定位：原材料 §4；
- 字段结果：材料没有规定非法尝试后字段如何变化，因此不得声称状态或库存保持不变。演示可选择不执行该源操作，但要把“不执行”标为教学界面设计。

### 第二步：设置领取条件

允许读者在教学情境中将预约设为“有效”，并将导览设为“完成”。

这两个设置入口属于教学构造，只用于探索规则。原材料没有规定现实中如何完成预约或导览。

设置条件时：

- 只更新当前教学输入；
- 不自动把状态改为“已核验”；
- 不自动减少库存；
- 不显示已经领取。

理由是依据原材料 §3，满足条件后仍需在“未核验”状态操作“核验”，状态才会变为“已核验”。

### 第三步：操作核验

起始信息：

- 状态“未核验”；
- 预约“有效”；
- 导览“完成”；
- 库存 2。

操作：“核验”。

结果依据原材料 §3：

- 状态变为“已核验”；
- 库存仍为 2。

“库存仍为 2”可直接表述，因为 §3 明确规定核验不改变库存。

反馈应指出：

- 两项必要条件均满足；
- 核验已完成；
- 当前只是“已核验”，尚未领取；
- 库存仍须在领取时单独判断。

### 第四步：操作领取

起始信息：

- 状态“已核验”；
- 库存 2。

操作：“领取”。

结果依据原材料 §4：

- 状态变为“已领取”；
- 库存由 2 减少为 1。

反馈应同时说明状态变化与库存变化，不得只显示“领取成功”。如果使用“成功”一词，须紧邻解释为本次规则中“状态变为已领取且库存减少 1”，避免把它扩展为现实业务的完整成功。

### 第五步：操作归还

起始信息：

- 状态“已领取”；
- 库存 1。

操作：“归还”。

结果依据原材料 §5：

- 状态变为“已归还”；
- 库存由 1 增加为 2。

反馈应说明：

- 归还只在“已领取”状态可用；
- 本次归还后状态为“已归还”；
- 材料没有规定“已归还”后的新一轮领取路径。

### 第六步：重新开始

操作：“重新开始”。

结果依据原材料 §7：

- 清除本轮操作；
- 库存恢复为 2；
- 状态恢复为“未核验”；
- 预约恢复为“无效”；
- 导览恢复为“未完成”。

相邻提示必须说明：

- 这是原材料规定的教学演示恢复方式；
- 不表示现实系统具有同名控件；
- 不表示现实业务记录被删除。

## 六、条件缺失分支

该部分采用独立题设，每次进入时恢复明确题设，不继承正常流程的状态。

### 情境一：两项条件都缺失

当前信息：

- 状态“未核验”；
- 预约“无效”；
- 导览“未完成”；
- 库存 2。

操作：“核验”。

依据原材料 §3，结果为：

- 状态保留“未核验”；
- 指出缺少“有效预约”和“已完成导览”；
- 库存仍为 2。

### 情境二：只有预约有效

当前信息：

- 状态“未核验”；
- 预约“有效”；
- 导览“未完成”；
- 库存 2。

操作：“核验”。

结果：

- 状态保留“未核验”；
- 指出缺少“已完成导览”；
- 库存仍为 2。

### 情境三：只有导览完成

当前信息：

- 状态“未核验”；
- 预约“无效”；
- 导览“完成”；
- 库存 2。

操作：“核验”。

结果：

- 状态保留“未核验”；
- 指出缺少“有效预约”；
- 库存仍为 2。

三个情境的反馈均应引用原材料 §2、§3，并强调两项条件缺一不可。

体验通行证如被纳入比较，只能显示：

- 它允许观察；
- 它不能替代预约；
- 它不能替代导览。

不得为体验通行证添加期限、持有人资格或其他效果。

---

## 七、库存为零分支

### 起始题设

教学构造设定：

- 状态“已核验”；
- 库存 0。

同时明确：此处是为演示 §4 的库存为零分支而设定的独立情境，并非从 §1 初始库存自然演算得到的当前记录。

### 操作与结果

操作：“领取”。

依据原材料 §4：

- 显示“等待补充”；
- 状态保留“已核验”；
- 库存保持 0。

反馈应说明：

- 领取操作在“已核验”状态下可发起；
- 库存为零使其进入“等待补充”结果；
- “等待补充”不等于已经领取；
- 材料没有规定何时补充、由谁补充或补充后的自动行为。

不得展示预计等待时间或保证后续领取。

---

## 八、取消预约分支

### 情境一：核验前取消

起始信息：

- 状态“未核验”；
- 预约“有效”；
- 导览“完成”；
- 库存 2。

操作：“取消”。

依据原材料 §6：

- 预约变为“无效”；
- 状态回到“未核验”；
- 导览仍为“完成”；
- 库存仍为 2。

虽然状态原本已经是“未核验”，仍应展示取消规则规定的目标状态，不应因为值相同而省略该结果。

### 情境二：核验后、领取前取消

起始信息：

- 状态“已核验”；
- 预约“有效”；
- 导览“完成”；
- 库存 2。

操作：“取消”。

结果：

- 预约变为“无效”；
- 状态回到“未核验”；
- 导览仍为“完成”；
- 库存仍为 2。

该情境最适合说明取消与“重新开始”的差异：

- 取消保留导览完成情况和库存；
- “重新开始”恢复 §1 的全部初始值。

### 情境三：领取后或归还后取消

分别设置状态“已领取”和“已归还”。

依据原材料 §6：

- 取消不可用。

教材界面可以阻止演示操作或在尝试后显示不可用反馈，但必须标明这种阻止方式属于设计判断。原材料只规定取消不可用，没有规定现实界面采用隐藏、禁用还是错误提示。

对于不可用尝试，材料未规定其他字段如何变化，教材不得将“字段保持不变”冒充为源规则。

## 九、取消与“重新开始”的并列比较

| 比较项 | 取消 | 重新开始 |
|---|---|---|
| 身份 | 活动规则中的操作，依据 §6 | 教学演示恢复方式，依据 §7 |
| 触发范围 | 领取前可用；“已领取”或“已归还”时不可用 | 原材料规定用于教学演示恢复 |
| 预约 | 改为“无效” | 恢复为“无效” |
| 访客状态 | 回到“未核验” | 恢复为“未核验” |
| 导览 | 明确保留当前完成情况 | 恢复为“未完成” |
| 库存 | 明确不变 | 恢复为 2 |
| 本轮操作 | 未规定清除 | 明确清除 |
| 现实系统含义 | 材料规定的取消规则 | 不表示现实系统必须有同名控件 |

比较表中的“恢复”均只适用于材料明确列出的字段，不得扩展到现实日志、账户或其他未定义对象。

## 十、交互反馈规范

每次反馈至少包含：

1. 当前题设和状态；
2. 用户刚执行的单个操作；
3. 判断：允许、不可用或材料未覆盖；
4. 明确变化的字段；
5. 原材料明确规定保持不变的字段；
6. 未规定的字段或后续；
7. 判断理由及段落定位；
8. 返回、改选、重试或重新开始的方式。

不得用颜色单独表示允许与禁止。应同时提供文字标签，例如“可操作”“不可用”“材料未覆盖”。

读者改变预约或导览条件后：

- 旧反馈应清除或明确标为已失效；
- 新判断只在读者重新提交相应操作后显示；
- 改变条件本身不等于已经核验。

读者重试独立分支时，应恢复该分支明确列出的题设，而不是隐式继承上一分支的状态。

---

## 十一、教学自检设计

自检只用于核对本次回答，不生成总分、能力等级或“已掌握”结论。

### 自检一：正常路径排序与解释

题设：

- 状态“未核验”；
- 预约“有效”；
- 导览“完成”；
- 库存 2。

任务：说明如何到达“已领取”，并列出每次操作后的状态和库存。

可靠判准：

- 先操作“核验”，状态变为“已核验”，库存仍为 2，依据 §3；
- 再操作“领取”，状态变为“已领取”，库存变为 1，依据 §4；
- 不能把满足条件直接等同于已经核验或已经领取。

常见误区：

- 跳过核验；
- 在核验时减少库存；
- 把“已核验”解释为已获得材料包。

### 自检二：识别缺失条件

题设：

- 状态“未核验”；
- 预约“有效”；
- 导览“未完成”。

任务：判断核验结果并说明反馈内容。

可靠判准：

- 状态保留“未核验”；
- 指出缺少“已完成导览”；
- 库存不变；
- 依据 §2、§3。

### 自检三：库存为零

题设：

- 状态“已核验”；
- 库存 0。

任务：说明操作“领取”后的结果。

可靠判准：

- 显示“等待补充”；
- 状态保留“已核验”；
- 库存保持 0；
- 不能称为已经领取；
- 依据 §4。

### 自检四：比较取消与重新开始

题设：

- 状态“已核验”；
- 预约“有效”；
- 导览“完成”；
- 库存 2。

任务：分别说明“取消”和“重新开始”的结果。

可靠判准：

- 取消使预约无效、状态回到“未核验”，但导览完成情况和库存不变，依据 §6；
- “重新开始”清除本轮操作并恢复 §1 的全部初始值，依据 §7；
- 应指出“重新开始”是教学演示恢复方式，不证明现实系统具有同名控件。

### 自检五：识别材料边界

任务：判断以下说法能否由材料推出：

- 多人同时领取时如何扣减库存；
- 预约在多久后失效；
- “等待补充”需要等待多长时间；
- 现实系统一定有“重新开始”按钮。

可靠判准：

- 四项均不能由现有材料推出；
- 多人并发、预约时效和跨活动规则明确不在范围，依据 §8；
- 等待时长未提供；
- §7 明确否定了对现实系统同名控件的保证。

对于材料未覆盖的问题，只给“无法依据本材料判断”及缺失项，不设置虚构的唯一答案。

## 十二、可用性与版面要求

这些要求属于设计判断，需在成品阶段另行检查：

- 当前状态、预约、导览和库存始终使用文字显示；
- 操作后的字段变化同时给出变化前与变化后；
- 关键条件、例外和材料边界保持常显；
- 不依赖悬停才能读取规则；
- 不以颜色作为唯一反馈；
- 操作入口具有清楚名称和当前可用状态；
- 键盘焦点顺序应与阅读顺序一致；
- 窄屏下规则依据不得与对应反馈分离；
- 动态反馈出现后，应能被辅助技术感知；
- “返回”“重试”“重新开始”的影响范围须在操作前可知。

以上均为拟检查项目，并非已经通过可访问性或操作测试。

## 十三、作者交付前核对清单

- 是否明确教材仅适用于单名访客和普通材料包？
- 是否完整呈现预约有效与导览完成缺一不可？
- 是否将满足条件与执行“核验”区分开？
- 是否将“已核验”与“已领取”区分开？
- 是否在核验结果中明确库存不变？
- 是否在领取结果中同时处理状态和库存？
- 是否完整呈现库存为零时的三项结果？
- 是否完整呈现归还后的状态和库存变化？
- 是否分别呈现取消对预约、状态、导览和库存的影响？
- 是否说明“已领取”与“已归还”时取消不可用？
- 是否将取消与“重新开始”的触发和字段结果分开？
- 是否明确“重新开始”不证明现实系统有同名控件？
- 是否把教学设置入口、界面阻止行为和反馈清除标为教学构造或设计判断？
- 是否将每个操作固定在明确当前状态下判断？
- 是否分别标明允许、不可用和材料未覆盖？
- 是否避免为未述字段补写变化、保持或恢复？
- 是否避免推导多人并发、预约时效、补充时间和跨活动规则？
- 是否让每道自检题的题设、判准、理由和定位使用相同前提？
- 是否避免用完成、答对或点击次数推断读者能力？
- 是否将拟检查项目与已经验证的事实分开？

本指南是教材内容与交互行为的设计说明，不代表教材已经制作、发布、测试或验收，也不证明其能够改善理解、形成稳定掌握或全面满足可访问性要求。
