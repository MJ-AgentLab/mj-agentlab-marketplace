# 《活动材料包领取：资格核验与库存边界》交互教材绘制指南

## 一、确认目标

- 读者：现场工作人员。
- 使用任务：处理普通材料包的资格核验与库存边界。
- 理解问题：核验、领取、归还和库存耗尽如何关联。
- 教学完成范围：帮助读者依据材料判断单名访客当前可以执行什么操作，以及访客状态和库存会发生哪些有据变化。
- 不作出的结论：本指南设计不证明读者已经稳定掌握规则，也不代表教材已经完成可访问性或实际操作验证。

## 二、材料范围与依据标记

### 原材料

《活动材料包领取说明》，修订 1，§1–§8；本次已完整读取。

适用范围为普通材料包、当前仅一名访客操作。工作人员试用证、多人并发、预约时效和跨活动规则不在材料覆盖范围内。

### 已核验背景

无。本指南不引入外部制度或现实活动流程。

### 全篇归因标记

教材中的规则、示例、模拟反馈和自检反馈均应就地使用以下标记：

- “原材料”：来自《活动材料包领取说明》，并注明具体段落。
- “教学构造”：为解释规则而虚构的固定情境、输入或示例，不代表活动记录。
- “设计判断”：教材的组织方式、交互入口、提示、高亮、反馈清除等新增行为。
- “未覆盖”：原材料没有给出足够规则，不能自行补成答案。

相邻的原材料不能替新增教学行为背书。每个新增入口、提示和反馈结果都要单独标明“设计判断”及适用范围。

## 三、全篇常显的核心结论

教材概览、条件模拟、示例、反馈、恢复说明和教学自检都应持续保留以下结论：

1. 预约有效与导览完成缺一不可，只有两项同时满足才具备核验通过的条件。体验通行证只能用于观察，不能替代预约或导览。  
   依据：原材料 §2。

2. “已核验”不等于“已领取”，也不保证库存充足。  
   依据：原材料 §8。

3. 领取需要同时满足访客状态为“已核验”和库存大于 0。库存为 0 时不会领取成功，也不会减少库存。  
   依据：原材料 §4。

4. 归还只适用于“已领取”状态。归还后访客状态变为“已归还”，库存增加 1。  
   依据：原材料 §5。

5. 库存耗尽后的“等待补充”只是材料规定的显示结果；材料没有规定如何补充库存、由谁补充或补充多少。  
   依据：原材料 §4、§8；补充动作属于未覆盖事项。

## 四、完整源规则单元

所有演示和模拟必须先让读者能够查看这一完整规则单元，不能仅凭初始面板或前一个示例补足条件。

### 1. 初始状态

- 普通材料包库存为 2。
- 访客状态为“未核验”。
- 预约无效。
- 导览未完成。
- 当前仅有一名访客操作。

依据：原材料 §1。

“库存”“访客状态”“预约状态”和“导览完成情况”是不同字段，显示时应分别命名，不用一个笼统的“当前状态”吞并。

### 2. 资格条件

预约有效且导览完成者可以领取一个普通材料包，两项条件缺一不可。体验通行证仅允许观察，不能替代其中任何一项。

依据：原材料 §2。

这里的“可以领取”仍须与核验、访客状态和库存规则结合理解，不能改写为材料包已经领取。

### 3. 核验

必要当前状态：访客状态为“未核验”。

直接操作：核验。

结果：

- 预约有效且导览完成时，访客状态变为“已核验”。
- 任一条件不满足时，访客状态保留“未核验”，并指出缺少预约有效、导览完成，或同时缺少两项。
- 核验不改变库存。

依据：原材料 §3。

材料只规定了“未核验”状态下的核验结果。其他访客状态再次核验时会发生什么，属于未覆盖，不能自行显示为成功、禁止或状态不变。

### 4. 领取

必要当前状态：访客状态为“已核验”。

直接操作：领取。

结果：

- 库存大于 0时，访客状态变为“已领取”，库存减少 1。
- 库存为 0 时，显示“等待补充”，访客状态保留“已核验”，库存不变。
- 其他访客状态不可领取。

依据：原材料 §4。

“等待补充”不得画成新的访客状态；材料明确保留的访客状态仍是“已核验”。

### 5. 归还

必要当前状态：访客状态为“已领取”。

直接操作：归还。

结果：

- 访客状态变为“已归还”。
- 库存增加 1。
- 其他访客状态不可归还。

依据：原材料 §5。

材料没有说明归还后可以再次核验或再次领取，不能自行续接循环。

### 6. 取消预约

触发范围：领取前可以取消预约；处于“已领取”或“已归还”时不可用。

直接操作：取消预约。

结果：

- 预约变为无效。
- 访客状态回到“未核验”。
- 导览完成情况不变。
- 库存不变。

依据：原材料 §6。

“已核验”且因库存为 0 显示“等待补充”时，访客仍未领取，因此仍处于材料所说的“领取前”。教材可以据此显示取消预约规则，但必须同时显示访客实际状态仍为“已核验”。

### 7. 重新开始

直接操作：重新开始。

结果：清除本轮操作，恢复全部初始值：

- 库存恢复为 2。
- 访客状态恢复为“未核验”。
- 预约恢复为无效。
- 导览恢复为未完成。

依据：原材料 §1、§7。

“重新开始”是材料明确规定的教学演示恢复方式，不表示现实系统必须存在同名操作，教材中必须常显这一边界。

## 五、教材整体布局

### 1. 规则概览区

先并列呈现四条主线：

- 条件线：预约有效与导览完成共同决定核验能否通过。
- 状态线：未核验、已核验、已领取、已归还。
- 库存线：初始为 2；成功领取时减 1；成功归还时加 1；库存为 0 的领取不改变库存。
- 边界线：库存补充、多用户并发、预约时效和跨活动状态均未规定。

状态线只表示材料明确出现的状态及有据转换，不暗示这些状态互斥且穷尽所有现实情形，也不把页面阅读顺序解释成唯一业务路径。

### 2. 当前情境区

同时显示：

- 预约是否有效；
- 导览是否完成；
- 访客状态；
- 当前库存；
- 最近一次直接操作；
- 最近一次操作结果或未覆盖提示。

“最近一次操作”和反馈记录属于设计判断，仅服务当前教学回合，不属于原材料规定的业务字段。

### 3. 关系说明区

使用并列关系表达，不把整个过程画成无条件直线：

- 预约有效与导览完成共同支持核验通过。
- 核验通过产生“已核验”状态，但不改变库存。
- “已核验”与库存大于 0 共同支持成功领取。
- 成功领取产生“已领取”状态并使库存减少 1。
- “已领取”支持归还；归还产生“已归还”状态并使库存增加 1。
- “已核验”但库存为 0 时，结果是等待补充，访客仍保持“已核验”。

每条连接都应注明依据段落和适用条件。

## 六、核心交互：条件与库存模拟

### 用途

让现场工作人员分别判断资格条件、访客状态和库存如何共同影响操作结果。

### 教学输入

允许读者在教学范围内选择：

- 预约有效或无效；
- 导览完成或未完成；
- 库存为 0、1 或 2；
- 当前访客状态；
- 单个直接操作。

这些可选库存值属于教学构造，仅用于覆盖初始库存、库存尚有余量和库存耗尽三类情境，不代表原材料将库存全域限定为 0 至 2。原材料没有规定库存上下界或外部补充方式。

### 操作规则

每次只提交一个直接操作。提交前应固定并显示当前访客状态、预约、导览和库存；不得把“修改条件”与“执行核验”合成同一次动作。

修改预约、导览或教学库存输入属于设计判断，只调整模拟题设，不表示现实业务动作已经发生。

### 反馈格式

每次反馈依次列出：

1. 当前事实；
2. 本次直接操作；
3. 命中的原材料规则及段落；
4. 操作是否允许、禁止或未覆盖；
5. 访客状态的有据结果；
6. 库存的有据结果；
7. 其他材料明确结果；
8. 材料未说明的字段或后续事项。

没有被材料提及的字段不得自动标成“不变”。只有原材料明确说明不变的字段，才能给出保持结论。

## 七、重点演示序列

以下均为教学构造，不是实际活动记录。每一步只执行一个直接操作。

### 演示一：从条件不足到核验通过

起始题设：

- 访客状态为“未核验”；
- 预约无效；
- 导览未完成；
- 库存为 2。

步骤与反馈：

1. 执行核验：预约与导览均不满足，访客保留“未核验”，指出缺少两项条件；库存仍为 2。  
   依据：原材料 §3。

2. 将预约改为有效：这只是教学题设调整，不代表核验已经自动发生。  
   身份：设计判断。

3. 执行核验：导览仍未完成，访客保留“未核验”，指出缺少导览完成；库存仍为 2。  
   依据：原材料 §3。

4. 将导览改为完成：这只是教学题设调整，访客仍须再次执行核验。  
   身份：设计判断。

5. 执行核验：两项条件均满足，访客变为“已核验”；库存仍为 2。  
   依据：原材料 §3。

演示重点：满足条件不等于已经执行核验，核验通过也不等于已经领取。

### 演示二：核验通过且库存充足

起始题设：

- 预约有效；
- 导览完成；
- 访客状态为“未核验”；
- 库存为 2。

先执行核验，再执行领取：

- 核验后访客变为“已核验”，库存仍为 2。依据：§3。
- 领取后访客变为“已领取”，库存变为 1。依据：§4。

不得把两个操作合并成“一次领取流程”，因为两次操作具有不同前提和字段结果。

### 演示三：库存耗尽

起始题设：

- 访客状态为“已核验”；
- 库存为 0；
- 预约有效且导览完成。

执行领取后：

- 显示“等待补充”；
- 访客状态保留“已核验”；
- 库存仍为 0。

依据：原材料 §4。

同时显示边界提示：原材料没有规定补充库存的操作、触发者、数量或时间，因此演示到此不能自动增加库存，也不能自动完成领取。

### 演示四：领取后归还

起始题设：

- 访客状态为“已领取”；
- 库存为 1。

执行归还后：

- 访客状态变为“已归还”；
- 库存变为 2。

依据：原材料 §5。

演示结束后不要自动返回“未核验”或“已核验”；材料没有规定该转换。需要重新演示时，使用材料规定的“重新开始”。

## 八、不可用与未覆盖反馈

反馈必须区分“材料明确禁止”和“材料没有说明”。

### 明确不可用

- 非“已核验”状态执行领取：不可领取。依据：§4。
- 非“已领取”状态执行归还：不可归还。依据：§5。
- “已领取”或“已归还”状态取消预约：不可用。依据：§6。

### 未覆盖

- 非“未核验”状态再次执行核验。
- 现实活动中如何补充库存。
- 补充库存后是否自动完成此前未成功的领取。
- “已归还”后能否再次领取。
- 多名访客同时操作时如何分配库存。
- 预约何时失效，以及是否跨活动有效。

未覆盖反馈应说明缺少什么规则及影响范围，不能显示为“操作失败”“输入无效”或“状态保持不变”。

## 九、重复操作与生命周期

- 每次操作后，以最新的访客状态和库存作为下一次操作的当前态。
- 修改教学条件不自动复位其他字段，也不表示某项源操作已经发生。
- 成功领取后再次领取属于“已领取”状态下的领取，因此依据 §4 判为不可领取。
- 成功归还后再次归还属于“已归还”状态下的归还，因此依据 §5 判为不可归还。
- 核验失败后访客仍为“未核验”，如条件随后改变，可再次按最新题设执行核验；材料没有规定核验次数限制。
- 取消预约后，访客状态回到“未核验”，导览完成情况和库存按 §6 保留原值。
- 执行“重新开始”后，本轮全部操作和教学反馈失效，并恢复 §1 的全部初始值。源恢复结果依据 §7；清除页面选择、高亮和旧反馈属于设计判断，仅适用于教材界面。

## 十、反馈与恢复设计

### 局部反馈

反馈不能只说“成功”或“失败”，应明确：

- 为什么允许、不可用或未覆盖；
- 哪些条件满足或缺失；
- 哪个访客状态发生了什么变化；
- 库存是否有原材料明确规定的变化；
- 对应段落；
- 常见误区。

例如，库存为 0 时的领取反馈要同时指出：

- 操作前访客已经“已核验”；
- 库存条件不足；
- 结果为“等待补充”；
- 访客仍是“已核验”；
- 库存不变；
- 这不等于资格核验失效。

### 改选与重试

修改输入后，旧反馈应明确标记为失效；再次提交时，只依据新的当前态判断。旧反馈失效属于设计判断，不改变任何原材料字段。

### 回退

若提供查看前一步的入口，应仅用于回看教学记录，不自动改写当前业务题设。若设计为恢复到前一步题设，必须明确列出被恢复的教学字段；该行为属于设计判断，不能称为原材料规定的撤销。

### 重新开始

“重新开始”应恢复 §1 的全部初始值，并清除本轮教学选择和反馈：

- 恢复源字段的依据：原材料 §1、§7。
- 清除选择、高亮和反馈的依据：设计判断，理由是避免旧反馈被误用于新一轮题设。
- 适用范围：仅本教材演示，不代表现实系统存在同名控件。

## 十一、教学自检设计

自检用于练习规则解释，不输出总分、能力等级或长期掌握结论。

### 自检一：核验条件

给定题设：

- 访客状态为“未核验”；
- 预约有效；
- 导览未完成；
- 库存为 2；
- 执行核验。

可靠判准：

- 访客保留“未核验”；
- 指出缺少导览完成；
- 库存仍为 2。

依据：原材料 §3。

误区反馈：预约有效只是两项必要条件之一；库存是否充足不改变核验条件。

### 自检二：核验与领取的区别

给定题设：

- 预约有效；
- 导览完成；
- 访客刚完成核验；
- 库存为 0。

要求读者判断当前访客状态和下一次领取结果。

可靠判准：

- 核验后状态为“已核验”；
- 执行领取时显示“等待补充”；
- 访客保留“已核验”；
- 库存保持为 0。

依据：原材料 §3、§4、§8。

误区反馈：“已核验”只表示资格条件已通过核验，不保证库存充足或材料包已经领取。

### 自检三：领取与归还的库存关系

给定题设：

- 访客状态为“已核验”；
- 库存为 1；
- 先领取，再归还。

可靠判准：

- 领取后状态为“已领取”，库存变为 0；
- 归还后状态为“已归还”，库存变为 1。

依据：原材料 §4、§5。

反馈应分别解释两次操作，不能只检查最终库存，因为相同最终库存不能证明中间状态判断正确。

### 自检四：库存耗尽后的后续

给定题设：

- 访客状态为“已核验”；
- 库存为 0；
- 领取结果已显示“等待补充”。

要求读者说明如何补充库存并继续领取。

判准性质：不可靠，不能自动判定唯一答案。

有界参考：

- 材料能够确定当前访客仍为“已核验”、库存仍为 0。
- 材料没有规定补充库存的方式或补充后的后续动作。
- 应将后续标为待补规则，而不是虚构补充按钮、自动领取或等待时间。

依据：原材料 §4、§8。

### 自检反馈生命周期

- 未提交、沉默或关闭自检均保持“待答”，不判断为知识错误。
- 改答后旧判断清除或明确失效。
- 新提交只依据当前题设和当前回答反馈。
- 重做时清除本题选择和反馈，并恢复题目明确给出的题设。
- 一次回答正确只说明该次回答符合判准，不证明稳定掌握。

以上均为设计判断，适用于本教材自检。

## 十二、视觉与可访问性待检查项

绘制时应确保：

- 预约、导览、访客状态和库存都有文字名称，不只用颜色区分。
- “等待补充”与“已核验”同时可见，避免被误读为同一状态字段。
- 操作是否可用、不可用或未覆盖均有文字说明。
- 条件、例外、依据和库存结果无需悬停才能发现。
- 比较两个情境时尽量并列显示，避免读者依赖前一画面的记忆。
- 键盘焦点顺序、缩放、窄屏换行和反馈朗读顺序列为制作后的待检查事项。

这些是拟检查项目，不表示已经完成实际可访问性验证。

## 十三、作者交付前核对清单

- 是否在首次演示前完整呈现了 §1–§8 中与操作有关的规则？
- 是否始终把“预约有效”和“导览完成”作为两个必要条件？
- 是否避免把满足条件写成核验已经自动发生？
- 是否避免把“已核验”写成已经领取或保证有库存？
- 是否把库存为 0 的结果写全：等待补充、保留已核验、库存不变？
- 是否仅在成功领取时减少库存，并仅在成功归还时增加库存？
- 是否把取消预约和重新开始的动作、对象及字段结果分别写全？
- 是否把“等待补充”与访客状态分开？
- 是否逐项区分“明确不可用”和“未覆盖”？
- 是否没有虚构库存补充规则、预约时效、多人并发规则或跨活动行为？
- 是否为每个教学构造和设计判断就地标明身份、理由与范围？
- 是否在改答、重试、回退和重新开始后明确旧反馈是否失效？
- 是否没有用最终库存相同来掩盖中间状态或操作差异？
- 是否将拟检查与已经验证的事项分开陈述？

本指南用于后续教材绘制与审校，不等同于教材已经制作、发布、测试或验收。
