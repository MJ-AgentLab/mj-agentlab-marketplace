# 未证环境原因的通用处理建议

这是通用方法建议，未修改运行资源、输入、判准或控制，不构成行为通过证据。

将用户请求的范围、技能的公开能力和工具的实际返回分开判断。请求超出公开能力时，依据技能合同说明边界；拒绝理由不需要附加未经证实的环境限制，也不扩大到本来允许的只读范围。

工具拒绝只能支持“这一请求被拒绝”及返回中明确给出的事实。若返回只有概括性的策略拒绝，原因保持未知；不得据此认定缓存、某类路径、整个工作区或全部只读请求均被禁止，也不得猜测是权限、沙箱、文件内容或调用形态导致。未尝试的访问保持未验证，不能写成不可能。

实际成功的读取、被截断的返回、后续补读和仍未读取的内容分别报告。文件存在、命令成功、已收到全文和已完成任务是不同事实；完整读取声明必须与实际接收范围一致，不能由模型自述替代。不得为弥补错误原因而编造成功、继续被拒绝的动作或追认未执行检查。

若仍有合同内的下一步，以已有材料和确实可用的只读能力继续；确有必要缺口时，只请求最小补充，并清楚区分“缺少材料”与“尚未核实访问能力”。读者、使用任务和理解问题仍须按原确认门槛处理，范围拒绝、环境描述、推荐或沉默均不代替明确确认。

建议优先修正通用指令中的证据表达顺序，而非增加固定领域答案、实例化测试规则或放宽量表。每次修正后用相同冻结输入和真实缓存新调用验证，保留原失败及实际工具事件。
